# PiKoSoL Host Platform: HTML, Ethernet, игры, приборы и библиотека 32 ГБ

**Статус: архитектурная концепция / NOT IMPLEMENTED.**  
**Дата:** 23.11.2026. Основа для идеи — [аппаратно проверенный Ethernet LA16](README.md), уже существующие PiKoSoL GPIO и HTML/Web Serial проекты. **Это не новая прошивка и не объявление аппаратного BOARD PASS для управления устройствами.**

## 1. Система

Цель — стабильная базовая конфигурация FPGA, а на хосте — красивый графический каталог различных приборных режимов, игр, учебных приложений, сервисов и контроллеров. Одна аппаратная платформа может использоваться для разных задач **без замены bitstream**, если все нужные аппаратные функции уже входят в эту конфигурацию.

~~~text
32 GB накопитель на ПК/хосте (первый этап)
 | HTML/CSS/JS, игры, профили, ресурсы, логи
 v
CHUWI: браузер + локальный HTTP/WebSocket/Python bridge
 |                                            ^
 | команда JSON -> проверка -> UDP             | события/телеметрия
 v                                            |
Ethernet / RTL8201F / FPGA Tang Primer 20K Dock
 |  UDP RX -> parser -> ACK -> GPIO/MMIO      | UDP TX
 |  PicoRV32 (опциональный CPU), таймер, SPI, UART, PWM
 +-- PMOD: входы датчиков, выходы на драйверы
 +-- HDMI: отдельная аппаратная функция (не браузер)
 +-- microSD на Dock: отдельный будущий проверяемый путь
~~~

**Разделение:** HTML выполняется **на хосте в браузере**, не непосредственно в FPGA. Проекты с HTML как **панелью управления** и проекты игр с Verilog/HDMI — разные архитектуры. Чтобы запускать современную HTML-игру непосредственно на HDMI FPGA без хоста, нужен браузер/JS runtime/рендерер либо иной специальный механизм передачи изображения; существующий PiKoSoL этим не обладает.

## 2. Три разных типа режимов

| Режим | Где выполняется | Изменение FPGA .fs |
| --- | --- | --- |
| HTML/JS игра или панель | Браузер ПК, хост обслуживает файлы | Нет |
| BIN для PicoRV32 | Процессор в уже работающем совместимом PiKoSoL SoC | Нет, если ABI и оборудование совместимы |
| Нативный FPGA режим (RTL/HDMI) | Новая аппаратная конфигурация | **Да**, явная загрузка в **SRAM**, отдельное тестирование |

Выбор HTML-страницы не должен автоматически перепрограммировать FPGA. Возможность менять профили без перепрошивки ограничена уже существующим набором аппаратных ресурсов стабильной прошивки.

## 3. Библиотека приложений на 32 ГБ

Для первого этапа — **32-ГБ накопитель подключён к хосту**, приложение открывается локальным сервером в браузере. Тогда множество HTML-игр, программ, графики и медиа ограничены объёмом файлов, а не количеством логических ячеек ПЛИС.

Предлагаемая структура (пока не создана и не протестирована):

~~~text
PIKOSOL/
  manifest.json
  apps/
    games/pong/index.html
    games/breakout/index.html
    instruments/gpio-panel/index.html
    instruments/telemetry/index.html
    education/rv32i/index.html
  profiles/
    gpio.json
    telemetry.json
  assets/
  captures/
~~~

Ключевое требование: каталог указывает **runtime, capabilities, поддерживаемую прошивку/версию API и статус аппаратной проверки**. Игра HTML в браузере не обязана иметь какой-либо FPGA-бэкэнд. Приложение управления устройством обязательно должно пройти отдельную аппаратную приёмку. Нельзя автоматически объявлять уже существующие Verilog Pong и Breakout браузерными играми: опубликованный HTML у них служит интерфейсом управления.

Если имелась в виду именно **microSD 32 ГБ, вставленная в Dock**, это **другой этап**: подтвердить физический SPI/SD интерфейс, чтение секторов, FAT32, файловый каталог и сервис доступа к данным. Не подменять эту задачу чтением файлов на компьютере. Не форматировать и не записывать носитель без отдельного решения.

## 4. HTML-интерфейс и сеть

Обычный браузер не имеет API для прямых UDP-сокетов. Значит, потребуется:

~~~text
HTML/JS → WebSocket/HTTP localhost (CHUWI)
        → Python host bridge
        → UDP command → FPGA
        ← ACK/status/telemetry
        ← WebSocket event ← bridge
~~~

Это **план**, а не поведение оригинальной LA16. В оригинале проверено только **FPGA → ПК**; GUI LA16 пассивно получает UDP.

Для будущего протокола предлагаем отдельную версию и сообщения: HELLO/CAPABILITIES, READ, SET, ACK, EVENT, PING/PONG. Нужны sequence, тайм-аут, дубликаты, контроль длины, CRC/контроль целостности, whitelist команд, лимиты частоты команд, соответствие устройства и его firmware/ABI. Порты и IP можно сделать настраиваемыми. Открытая сеть и недоверенные клиенты не допускаются без дополнительной аутентификации/защиты.

## 5. Управление исполнительными устройствами

**Начинать только со штатного LED**, после проверки UDP RX. Переход на GPIO, PWM, реле, моторы, нагреватели и другие исполнительные устройства — отдельные этапы с аппаратными ограничителями. На плате и в системе обязательны безопасное состояние при потере связи, запрет неожиданных действий при старте, разрешённые диапазоны параметров, подтверждения фактически установленного состояния. Для потенциально опасных механизмов требуется независимый аппаратный аварийный останов; сеть не может быть единственным механизмом безопасности.

Возможный интерфейс прибора: главное меню → выбор типа/профиля → обнаружение устройства → чтение capabilities → ручное разрешение на управление → текущие показания → команды → подтверждения → журнал ошибок. Красивый интерфейс — это часть хост-приложения, а не доказательство готовности FPGA-контроллера.
