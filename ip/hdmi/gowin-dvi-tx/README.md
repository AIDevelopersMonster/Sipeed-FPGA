# Gowin DVI_TX — применение закрытого IP в Tang Primer 25K

**Назначение.** Заводской **IP-блок** GOWIN преобразует RGB888 + синхросигналы в дифференциальные TMDS-линии для DVI-видео по кабелю HDMI. Это **не заводская конфигурация FPGA**, не наш исходный HDMI-передатчик и не полноценное HDMI-аудио.

**Аппаратный факт:** 15.11.2026 на Tang Primer 25K + Dock через этот IP получены цветные полосы исходной лаборатории и затем **наш собственный статический экран KonSol 80×30, 640×480** (фотографически подтверждённый BOARD VIDEO PASS). Работа UART, файлового менеджера, длительная стабильность и STA-signoff этим не доказаны.

## Официальные ссылки и лицензирование

- [GOWIN DVI TX — страница IP](https://www.gowinsemi.com/en/support/ip_detail/48/).
- [GOWIN IP & Reference Design и ссылка на EULA](https://www.gowinsemi.com/en/support/ip/).
- [GOWIN DVI TX RX IP User Guide, IPUG938](https://www.gowinsemi.com/upload/database_doc/2720/document/69cab0e35c660.pdf).
- [GOWIN EDA / официальные лицензии](https://www.gowinsemi.com/en/document/main/database/14/?order=ASC&page=1&support_search=&type=category).

**Правовой статус:** DVI_TX — поставляемое производителем **зашифрованное проприетарное IP**, а не RTL под MIT/GPL/BSD. Права на учебный wrapper или на собственный RGB-генератор **не распространяются автоматически** на это ядро. GOWIN прямо подчиняет доступ к IP условиям EULA. Наличие `.ipc` и `.v` либо факт успешного синтеза сами по себе не определяют разрешения на передачу/публикацию IP и производных `.fs` — условия применимой лицензии нужно проверять отдельно. **Не включать защищённый `dvi_tx.v` в собственную публичную библиотеку и не обозначать его как open source.** Здесь публикуется только интерфейсная документация.

## Архитектура и интерфейс

```text
Собственная графика (KonSol / RGB8:8:8)
    red[7:0], green[7:0], blue[7:0]
    hsync, vsync, display_on
            |
            v
   DVI_TX_Top (GOWIN IP)
       I_rgb_clk, I_serial_clk, I_rst_n
            |
            v
  TMDS_CLK+/- и 3x TMDS_DATA+/- 
            |
            v
    PMOD DVI -> монитор
```

Минимальное соединение, проверенная схема сигналов:

```systemverilog
DVI_TX_Top i_dvi (
    .I_rst_n       (~rst),
    .I_serial_clk  (clk_125mhz),
    .I_rgb_clk     (pixel_clk_25mhz),
    .I_rgb_vs      (~vsync),
    .I_rgb_hs      (~hsync),
    .I_rgb_de      (display_on),
    .I_rgb_r       (red),
    .I_rgb_g       (green),
    .I_rgb_b       (blue),
    .O_tmds_clk_p  (TMDS_CLK_P),
    .O_tmds_clk_n  (TMDS_CLK_N),
    .O_tmds_data_p (TMDS_D_P),
    .O_tmds_data_n (TMDS_D_N)
);
```

**Внимание:** полярность HSYNC/VSYNC в примере инвертирована в wrapper, поскольку указанные сигналы исходного VGA-генератора активны по низкому уровню. Другой генератор обязан согласовать полярности и фазировку, нельзя копировать инверсии без проверки. При замене RGB не менять уже прошедшие аппаратную проверку PLL, CST, SDC и DVI_TX.

## Проверенная конфигурация для Primer 25K + Dock

| Параметр | Значение |
|---|---|
| FPGA | `GW5A-25A`, `GW5A-LV25MG121NC1/I0` |
| Gowin | `1.9.9Beta-4 Education` |
| Вход PLL | `50 MHz` на FPGA `E2` |
| Частота сериализации | `125 MHz`; RGB-пиксельный поток `25 MHz` |
| Разрешение | `640x480`, цвет `RGB888` |
| CLOCK TMDS | FPGA `H5 / J5` |
| DATA0 TMDS | FPGA `H8 / H7` |
| DATA1 TMDS | FPGA `G7 / G8` |
| DATA2 TMDS | FPGA `F5 / G5` |
| **Где PMOD** | **Разъём под USB-A — только так проверено оператором** |
| Запись | Только volatile SRAM `--run 2`, Flash не трогать |

Названия PMOD0, PMOD2, J4, J6 в разных схемах/платах и комментариях могут противоречить наблюдаемому расположению. Для **этого аппарата** используется место, где 15.11.2026 получено изображение: под USB-A. Не переносить модуль при следующих испытаниях.

## Получение и генерация IP

1. Установить GOWIN EDA с поддержкой GW5A-25A. В **IP Core Generator** выбрать **DVI TX** для своего кристалла.
2. Выбрать конфигурацию **`DVI_TX_Top`**, **`ELVDS=true`**, **`USING_EXTERNAL_CLOCK=true`** и сверить параметры/ограничения с версией EDA. Это конфигурация успешно собранного варианта; одноимённое корневое `dvi_tx` без внешнего тактового входа — **другой IP-вариант**, он не подходит к данному интерфейсу.
3. Сгенерировать защищённый `dvi_tx.v`, добавить его в Gowin-проект как `add_file -type verilog`. **В EDA 1.9.9Beta-4 команды Tcl `read_ipc` и `generate_target` при нашем испытании не поддерживались.**
4. Подключить PLL, собственную генерацию координат/синхронизации, наш RGB-генератор и неизменные проверенные `.cst`/`.sdc`.
5. `gw_sh.exe <build.tcl>` → `.fs` → анализ STA → **SRAM Program** → наблюдение изображения на мониторе.

В нашем исходном опыте основой сборочного wrapper была открытая учебная лаборатория, зафиксированная на commit `817bd4dac8ab45d5c22bdd78b441bedb80672cd0` репозитория [yuri-panchul/basics-graphics-music](https://github.com/yuri-panchul/basics-graphics-music). Отдельный учебный пример удалён из **нашего** GitHub; авторство исходной обвязки и модулей синхронизации этим не отменяется. Сама реализация DVI_TX принадлежит GOWIN.

## Что **не** предоставляет этот IP

- Нет HDMI-аудиопакетов, ACR/InfoFrame или встроенного звука.
- Нет VRAM, BRAM-текстового контроллера, файловой системы и UART-команд.
- Нет гарантии совместимости при переносе на другие пины, частоты или платы без пересборки и аппаратного теста.

**Рабочий потребитель:** [PR25-KonSol-DVI](../../../Tang-Primer-25K/Examples/PR25-KonSol-DVI/README.md). Для HDMI со звуком — отдельно проверенные A2600Nano / PR25-13, не этот IP.
