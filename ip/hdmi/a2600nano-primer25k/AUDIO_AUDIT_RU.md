# AUDIO_AUDIT_RU — точные настройки HDMI-звука A2600Nano v2.5

**Дата:** 2026-11-14. **Плата:** Tang Primer 25K / GW5A-25A + PMOD DVI. **Объект проверки:** только исходники `MiSTle-Dev/A2600Nano` релиза `v2.5`, commit `705bf787675579721d339806cb522905dec73ed3`, плюс наши PR25-08/09. **Факты:** неизменённый оригинальный .fs физически даёт видео и громкий игровой звук; PR25-08 физически даёт видео, **звук не слышен**; PR25-09 ещё не испытывался.

## 1. Это НЕ восьмибитный PCM-звук

Консоль Atari 2600 использует 8-битный 6507, но блок TIA формирует **два независимых звуковых канала** по регистрам:

- `AUDF0/1` — 5-битный делитель частоты;
- `AUDC0/1` — 4-битный тип тона/шума (polynomial LFSR, меандр и делители);
- `AUDV0/1` — 4-битная громкость от 0 до 15.

См. [TIA.vhd строки 1068–1080](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/TIA/TIA.vhd#L1068-L1080) и [audio_argh2600.vhd](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/TIA/audio_argh2600.vhd).

В [A2601top.vhd строки 298–299](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/A2601top.vhd#L298-L299) выход каждого из двух каналов фактически `aud0 = au0 ? av0 : 0`, `aud1 = au1 ? av1 : 0`. Это логически gated 4-bit amplitude, не 8-bit PCM.

## 2. Путь именно на Primer 25K

[Top-level TP25K строки 325–354](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/tang/primer25k/a2600_top_tp25k.vhd#L325-L354) подключает:

```vhdl
audio_l => signed("0" & audio0 & "0000000000"),
audio_r => signed("0" & audio1 & "0000000000"),
```

Значение игровой амплитуды `v` в пределах 0..15 масштабируется `v*1024`, давая **0..15360 = 0x0000..0x3C00** на канале. Старший бит равен 0, то есть исходный сигнал **неотрицательный**, относительно звукового нуля у него возможна DC-составляющая.

В [video.v строки 83–98](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/misc/video.v#L83-L98) 15-битный вход расширяется до 16 бит, затем применяется `system_volume`:

| `system_volume` | Операция RTL | Амплитуда до 16-битного HDMI |
|---|---|---|
| `0` | PCM 0 | 0 |
| `1` | арифметический сдвиг вправо 2 | 0..3840 (`0x0F00`) |
| `2` **default** | арифметический сдвиг вправо 1 | 0..7680 (`0x1E00`) |
| `3` | без сдвига | 0..15360 (`0x3C00`) |

По [sysctrl.v:115](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/misc/sysctrl.v#L109-L121) стандартно `system_volume <= 2'b10` (**50% амплитуды**). MCU может затем изменить настройку через команду `CMD4, id='A'` ([sysctrl.v:237](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/misc/sysctrl.v#L228-L240)). Комментарий меню у автора говорит про 33/66/100%, но фактический RTL реализует 25/50/100%. Поэтому реальная громкость сыгранной игры без чтения состояния MCU неизвестна.

В [video.v:245–255](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/misc/video.v#L242-L258) подключено:

```verilog
hdmi #(
    .AUDIO_RATE(48000),
    .AUDIO_BIT_WIDTH(16)
) hdmi (
    .clk_audio(clk_audio),
    .audio_sample_word({audio_vol_l, audio_vol_r}),
    // ... clocks, RGB and outputs ...
);
```

**Итого: игровая TIA с 4-битной громкостью -> 16-битная стереопара -> HDMI LPCM 48 kHz (номинал).** Резкость громких игровых шумов обусловлена формой и длительностью сигналов и последующим воспроизведением монитором/усилителем, а не 8-битной разрядностью HDMI.

## 3. Частоты (важное уточнение!)

В `gowin_pll_ntsc.ipc`: `ClkinClockFrequency=50`, `Clkout0ExpectedFrequency=143.182`. С `CLKDIV /5` это **~28.6364 MHz** для пикселей.

В [video.v:67–81](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/misc/video.v#L67-L81) макрос `PIXEL_CLOCK = 28542800`. Счётчик делает 297 периодов пиксельной частоты на *полупериод* `clk_audio`: `clk_audio` имеет один фронт через 594 пиксельных такта. При фактическом пиксельном такте ~28.6364 MHz:

```text
fs_actual = 28,636,400 / (297 * 2) = 48,209.43 Hz
fs_declared = 48,000 Hz
delta = +0.4363 %
```

Это **вычисление по параметрам RTL/IP, не измерение частотомером**. Важный факт: **наш PR25-08 использовал точно такой же divider 0..296 и приблизительно 48.2kHz.** Поэтому объяснять отсутствие аудио PR25-08 неправильной частотой генератора, не предъявив иных данных, нельзя.

У HDMI `AUDIO_RATE=48000`, audio packet `SAMPLING_FREQUENCY=4'b0010`. ACR-модуль вычисляет **N=6144** и формирует CTS-счётчик по исходному sample clock ([audio_clock_regeneration_packet.sv](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/hdmi/audio_clock_regeneration_packet.sv)). В `hdmi.sv` параметр `VIDEO_RATE=28E6` является авторским расчётным параметром, а не заменой реального FPGA PLL.

## 4. HDMI packet path

[packet_picker.sv](https://github.com/MiSTle-Dev/A2600Nano/blob/v2.5/src/hdmi/packet_picker.sv) захватывает `audio_sample_word[1:0]` по фронту `clk_audio`, переносит по синхронизатору в пиксельную область, набирает четыре стереосэмпла, а затем передаёт `Audio Sample Packet` в HDMI data island. Также формируются Audio Clock Regeneration и Audio InfoFrame для **двух каналов LPCM**.

Монитор получает звук именно по TMDS, без самостоятельного аудиопровода. Оригинальная прошивка на этом мониторе даёт слышимый звук — физический HDMI audio путь принципиально работоспособен.

## 5. Почему у нас тишина? Честное сравнение

| Свойство | Оригинальный A2600 v2.5 | PR25-08 (VIDEO PASS / AUDIO FAIL) | PR25-09 (не испытан) |
|---|---|---|---|
| Сам PCM вход | 4-битная TIA амплитуда 0..15, scaled, default 50% | bipolar square ±`0x1800` (= ±6144) | bipolar ±`0x3000` (= ±12288), 0.75s/0.25s |
| Параметры HDMI | LPCM stereo, 48kHz, 16-bit | те же | те же |
| Audio sample clock | 297x2 pixel ticks | **те же 297x2** | **те же 297x2** |
| Port binding | inline `{audio_vol_l,audio_vol_r}` | SV unpacked array `samples[1:0]` | inline `{audio_l,audio_r}` |
| Source waveform generation | игровой TIA, преобразованный в PCM | sample phase управляется пиксельным clock enable | sample phase обновляется на `posedge clk_audio` |
| Видео | образец BOARD PASS | BOARD PASS | NOT TESTED |
| Звук | слышно, громкий | **не слышно** | NOT TESTED |

**Уровень сигнала PR25-08 не обязан быть слабее оригинала.** Для симметричного меандра ±6144 пик равен ~19% от полной шкалы 16-bit signed, а оригинальный канал при default может достигать +7680, но переключается между 0 и +7680; его переменная составляющая при duty 50% имела бы амплитуду ±3840. Строгое сравнение субъективной громкости требует реального игрового содержимого и уровня усиления монитора. Простое увеличение тестового значения не является доказанным исправлением.

**Что не доказано:** причина отсутствия звука. Возможные направления — фактическая активность генератора PCM, синтез/соединение unpacked array к HDL-порту, audio sample buffer/пакеты в `packet_picker`, ACR/InfoFrame, конфигурация аудиовхода монитора. Стандартный HDMI видеосигнал не доказывает наличие корректных аудиопакетов. Полный отчёт STA и RTL-level audio trace PR25-08 отсутствуют.

## 6. Минимальный следующий тест

1. **Не трогать PR25-08** — сохранён VIDEO BOARD PASS.
2. Проверить уже опубликованный **PR25-09**, где audio waveform переведена в аудиотактовую область и используется авторская форма `.audio_sample_word({audio_l,audio_r})`; HDMI packet/PLL/TMDS без изменений.
3. На PR25-09 экранный квадрат становится **зелёным на время тона, красным на время паузы**. Это доказывает генерацию управляющей огибающей, но **не доказывает отправку audio data islands**.
4. Перед запуском снизить громкость монитора: PR25-09 peak PCM вдвое больше PR25-08, **примерно +6 dB** амплитуды. Исходный A2600 уже был субъективно громким.
5. Если индикатор работает и тишина сохраняется, потребуются диагностика упаковки аудиосэмплов и синтеза HDL, сведения монитора о распознанном аудиоформате; не подменять это очередным увеличением громкости.

**Никакого изменения оригинального `vendor/`, работающего PR25-08, PiKoSoL или FPGA Flash для данного аудита не требуется.**
