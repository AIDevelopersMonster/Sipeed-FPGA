# LiteX BIOS на Tang Nano 20K — полный практический справочник

[← BIOS](../README.md) · [← Tang Nano 20K](../../README.md) · **[Показать ROM Explorer v3.3](ROM_EXPLORER_GUIDE_RU.md)** · [Протоколы аппаратных испытаний](../../06-RV32-RAM-Diagnostics/README.md)

> Здесь мы работаем с **заводским LiteX SoC** платы **Sipeed Tang Nano 20K (GW2AR-18)**. Наша FPGA-конфигурация для этой платы **пока не создана**. Проверенные результаты относятся к конкретному заводскому образу, а не к любой версии LiteX.

## 1. Что такое LiteX и зачем нужен BIOS

**LiteX** — открытая система проектирования и сборки **систем-на-кристалле (SoC) для FPGA**. Она интегрирует процессор, память, системную шину (например, Wishbone), UART, таймер, контроллер SDRAM, ROM, периферию, генерирует адресную карту и программное обеспечение, включая **BIOS**. Не путать: **VexRiscv — процессор**, **LiteX — система, связывающая его с остальным аппаратным окружением**, **BIOS — программа для запуска и диагностики этого окружения**.

BIOS выполняет следующие задачи:

1. Обеспечивает старт процессора после сброса, настраивает C-окружение и системные регистры.
2. Инициализирует UART, при необходимости другие контроллеры и внешнюю SDRAM.
3. Выполняет начальную диагностику памяти и сообщает конфигурацию SoC.
4. Пытается загрузить приложение с предусмотренных сборкой носителей (например, serial boot; наличие других вариантов зависит от FPGA-конфигурации).
5. При отсутствии подходящей программы открывает **интерактивную консоль `litex>`** с командами просмотра памяти и запуска приложений.
6. Передаёт управление пользовательскому коду по указанному адресу, например `boot 0x40010000`.

Более общий **LiteX BIOS** имеет и другие команды/подсистемы; конкретный набор определяется возможностями собранной FPGA-системы. **Используйте `help` вашей платы как окончательный перечень**, не команды из случайного интернет-руководства.

## 3. Где хранится BIOS, где «прошивка», где наша программа

`LiteX BIOS` — **машинный код, доступный CPU через область ROM**; в нашем заводском SoC он отображён на `0x00000000–0x0001FFFF`. Он создан на базе исходников C/ассемблера LiteX и интегрирован в заводскую FPGA-конфигурацию (в терминах SoC — **integrated ROM**). **Мы читаем эту область, но не перезаписываем её.**

**FPGA bitstream** — отдельный объект: он конфигурирует логические блоки FPGA и создаёт весь SoC, включая ROM, шины и процессор. На плате предусмотрена внешняя конфигурационная Flash, но наша лаборатория не читала её образ целиком и не выполняла запись. Нельзя считать файл `PiKoSoL_LAB20_ROM_32KiB.bin` образом конфигурационной Flash — это **только CPU-visible BIOS ROM**, не `.fs`.

**SDRAM** (`0x40000000–0x407FFFFF`) — отдельная **энергозависимая** память для пользовательского кода и данных. В LAB-20.6 мы поместили `snapshot.bin` (740 байт) по `0x40010000`, снимок регистров — по `0x40011000`; затем выполнили `boot 0x40010000`. **Это не BIOS и не изменение Flash.**

## 4. Как посмотреть работу BIOS на реальной плате

Откройте UART-терминал с настройками **115200 8N1**, выберите правильный COM (в нашем опыте **COM25**). Не смешивайте этот порт с COM-портом Tang Nano 9K. При включении или аппаратном RESET ждите `litex>`. Если BIOS пробует serial boot и пишет `No boot medium found`, это не авария FPGA: просто не найден подходящий загрузочный образ.

Безопасные демонстрации:

```text
litex> help
litex> mem_list
litex> mem_read 0x000000B0 16
litex> mem_read 0x000080B0 16
litex> mem_read 0x000100B0 16
litex> mem_read 0x000180B0 16
litex> mem_read 0xF0003014
```

Сравните четыре одинаковые 16-байтные области ROM — это адресные зеркала. `0xF0003014` — регистр разрешения TX/RX-событий UART, в нашем эксперименте был `03 00 00 00`. **Перед доступом к иным адресам проверьте [карту памяти](MEMORY_MAP_RU.md) и [безопасность команд](COMMANDS_RU.md).** Чтение MMIO может иметь побочные эффекты — это не универсально «безопасная память».

Команды `mem_write`, `mem_copy`, `mem_test`, `boot` и особенно любые операции Flash **не относятся к обзорному read-only сценарию**. Пример записи в SDRAM допускается только по отдельной [проверенной инструкции LAB-20.6](../../REPRODUCE_LAB20_6_RU.md).

## 5. Как посмотреть BIOS в HTML: уже выложено, скачивать необязательно

**Online (GitHub Pages):** [PiKoSoL ROM Explorer v3.3](https://aidevelopersmonster.github.io/Sipeed-FPGA/lab20/rom-explorer/) — это **опубликованный адрес проекта**. HTML существует в GitHub, но **доступность опубликованной страницы не удалось проверить из текущей среды**. При недоступности онлайн используйте офлайн-файл.

**GitHub (точный исходный HTML):** [`index.html` в этой папке](index.html) и [исторический сайт в `docs/lab20/rom-explorer`](https://github.com/AIDevelopersMonster/Sipeed-FPGA/blob/main/docs/lab20/rom-explorer/index.html). GitHub показывает *код* файла, а не запускает интерактивную модель: нужно скачать **Raw**, либо открыть файл из локального клона.

**Offline:** достаточно открыть `index.html` в Chrome/Edge; ROM уже встроен внутрь HTML (не требуется обращаться к UART, JTAG, интернету, Python или серверу). Пошаговый запуск и интересные места — в [руководстве по ROM Explorer](ROM_EXPLORER_GUIDE_RU.md).

Для локального клона на новом ПК:

```powershell
git clone https://github.com/AIDevelopersMonster/Sipeed-FPGA.git C:\GitHub\Sipeed-FPGA
Set-Location C:\GitHub\Sipeed-FPGA\Tang-Nano-20K\BIOS\LiteX
Start-Process .\index.html
```

Автономная проверка соответствия встроенного ROM и BIN (если установлен Node.js 18+):

```powershell
node .\test_v32.js
```

Нужна строка: `PASS canonical32 image + HTML embedded ROM + mirror128 + CRC32`. Это **программный тест файлов**, а не новая аппаратная проверка.

## 6. Интересные точки исследования

**[Открыть семь демонстраций](DEMO_POINTS_RU.md)** — там указаны точные адреса, кнопки эмулятора, ожидаемый эффект и пределы того, что можно считать доказанным. Самое важное:

- `PC=0x00000000` — reset vector → переход к `0x000000B0`.
- `PC=0x00000020` — trap/exception vector; видим обработчик в коде, не заявляем факт реального IRQ.
- `PC=0x000047A4` — `uart_init`: чтение события `0xF0003010`, подтверждение, включение `ev_enable=3` и маски IRQ.
- `PC=0x00006644` — записанный CRC32 BIOS `F2B1F4F6`.
- Отображение 128-КиБ ROM-окна на **четыре совпадающих 32-КиБ периода**.
- **Самонаблюдение UART:** BIOS `mem_read` печатает перед замером FIFO, а наша RAM-программа считывает TXEMPTY до/после печати: **`1 → 0` на реальном FPGA**.
