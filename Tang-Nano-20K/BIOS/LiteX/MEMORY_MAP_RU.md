# Карта памяти LiteX / VexRiscv_Min — Tang Nano 20K

[← Справочник BIOS](README.md) · [Команды BIOS](COMMANDS_RU.md) · [Реконструкция UART](../../05-UART-CSR/CSR_UART_LAB20_5.md)

Это **наблюдаемая** карта заводского SoC, не универсальная схема всех конфигураций LiteX. [Полный ответ `mem_list`, 2026-11-08](../../LiteX-Closeout/MEM_LIST_HARDWARE_PASS_2026-11-08.md). Адрес — 32-разрядный адрес процессора RISC-V. **4 ГиБ адресного пространства Wishbone не равны объёму установленной памяти**.

| Диапазон / адрес | Назначение | Основание |
|---|---|---|
| `0x00000000–0x0001FFFF` | CPU-visible BIOS ROM, окно 128 КиБ | `mem_list` и полный read-only захват |
| `0x00000000–0x00007FFF` | Единственный уникальный 32-КиБ период ROM | SHA256, CRC и прямые чтения |
| `0x00008000–0x0001FFFF` | Повторяющиеся окна ROM с периодом `0x8000` | Прямые чтения `0xB0`, `0x80B0`, `0x100B0`, `0x180B0` |
| `0x10000000–0x10001FFF` | Внутренняя SRAM 8 КиБ | **Прямой аппаратный вывод `mem_list` 2026-11-08** |
| `0x40000000–0x407FFFFF` | MAIN_RAM, внешняя SDRAM 8 МиБ | `mem_list`, BIOS memtest и проверка загрузки 740/740 байт |
| `0x40010000–0x400102E3` | Наша RAM-программа `snapshot.bin`, 740 байт | Полный readback 740/740 и исполнение |
| `0x40011000–0x4001103B` | 60-байтный буфер снимка CSR/MMIO программы | Адреса в `snapshot.S`; отдельный аппаратный дамп после boot не снимался |
| `0xF0000000–0xF000FFFF` | Адресное окно CSR, 64 КиБ | **Прямой `mem_list`**, не перечень установленных регистров/устройств |
| `0xF0003000` | LiteX UART RX/TX data | ROM, LiteX исходники; **не делать произвольных read/write** |
| `0xF0003004` | UART `txfull` | Реальное чтение `0` |
| `0xF0003008` | UART `rxempty` | Реальное чтение `1` |
| `0xF000300C` | UART `ev_status` | Реальное чтение `1` |
| `0xF0003010` | UART `ev_pending` | Реальные значения `0` в BIOS и `1` в RAM-программе (разные моменты) |
| `0xF0003014` | UART `ev_enable` | Реальное чтение `3` |
| `0xF0003018` | UART `txempty` | Реальные значения `0` через BIOS, `1→0` при независимом снимке |
| `0xF000301C` | UART `rxfull` | Реальное чтение `0` |

## Два разных типа CSR

**CSR архитектуры RISC-V**: специальные регистры инструкций CPU `csrrs`, `csrrw`; пример `mstatus` (`0x300`), `mie` (`0x304`), `mtvec` (`0x305`) и VexRiscv-специфические `0xBC0` (IRQ_MASK), `0xFC0` (IRQ_PENDING). Это **12-битные номера**, не обычные физические адреса.

**LiteX peripheral CSR**: обычные **MMIO-регистры** по адресам `0xF000....` в 32-разрядном пространстве памяти; команды RV32I `lw/sw` через Wishbone. Поэтому `csr 0xBC0` и `0xF0003010` нельзя сравнивать как одну категорию регистров.

## Как образуется повторение ROM

Для окна `0x00000000–0x0001FFFF` наблюдение показывает: `фактическое смещение = адрес & 0x7FFF`. Это **факт отображения адресов в нашем испытании**. Такое поведение согласуется с автоматическим уменьшением интегрированного ROM в LiteX, но не доказывает точную раскладку ресурсов BRAM.

## Для чего карта нужна на практике

Выбираем **безопасные адреса** для чтения, отделяем код BIOS от программы в SDRAM, отличаем загрузку CPU от программирования FPGA Flash и можем сопоставлять строки дизассемблера с реальными MMIO-операциями.

**Не переносите карту на другую заводскую версию FPGA, на Tang Nano 9K или Primer 25K.** Физическая база UART, объёмы и подключённые устройства могут быть другими.
