# PiKoSoL ROM Explorer v3.3 — как открыть и изучать заводской LiteX BIOS

[← Справочник LiteX BIOS](README.md) · [Интересные точки](DEMO_POINTS_RU.md)

**Да: эмулятор уже существует и опубликован на GitHub.** Мы сами сделали автономную HTML-модель для прочитанного ROM заводского LiteX BIOS на Tang Nano 20K. Внутри HTML находится **ровно 32 КиБ уникального BIOS ROM**, взятого из аппаратного захвата. Плата не нужна, чтобы изучать машинные инструкции и переходы.

## Где открыть

- **[GitHub Pages — ROM Explorer v3.3](https://aidevelopersmonster.github.io/Sipeed-FPGA/docs/lab20/rom-explorer/)**. Это опубликованный адрес проекта; из текущей среды **не удалось подтвердить HTTP-доступность страницы**. Если не открывается, используйте локальную версию ниже.
- **[Файл `index.html` в нашей папке BIOS/LiteX](index.html)**. На странице GitHub выберите `Raw` или скачайте репозиторий: GitHub не выполняет JavaScript непосредственно при просмотре исходника.
- **[Оригинальный каталог приложения на GitHub](https://github.com/AIDevelopersMonster/Sipeed-FPGA/tree/main/docs/lab20/rom-explorer)**. Путь оставлен для GitHub Pages и старых ссылок.
- [Независимый бинарный образ ROM 32 КиБ](PiKoSoL_LAB20_ROM_32KiB.bin) · [манифест с SHA-256 и CRC](PiKoSoL_ROM_32KiB_manifest.json).

## Как запустить без интернета

Клонируйте проект (на новом ПК):

```powershell
git clone https://github.com/AIDevelopersMonster/Sipeed-FPGA.git C:\GitHub\Sipeed-FPGA
Set-Location C:\GitHub\Sipeed-FPGA\Tang-Nano-20K\BIOS\LiteX
Start-Process .\index.html
```

Файл **автономный**: он не обращается к COM/JTAG и не требует запущенного локального сервера, дополнительного ROM или прошивки платы. Если вы открываете только одиночный `index.html`, сохраните его с расширением `.html`, а не `.txt`.

Для независимого контроля данных требуется Node.js 18+:

```powershell
node .\test_v32.js
```

Ожидается `PASS canonical32 image + HTML embedded ROM + mirror128 + CRC32`. Этот тест **не моделирует точность FPGA по тактам** — только проверяет артефакты ROM/HTML.

## Шесть разделов интерфейса

| Вкладка | Для чего | Что сделать |
|---|---|---|
| **01 Исследователь** | Пошагово выполнять RV32I-инструкции из заводского BIOS, смотреть PC, x0…x31, память, CSR и последствия переходов | Нажать **Сброс**, затем **Шаг** или **+10 / +100 / +1000**; вернуть шаг кнопкой **Шаг назад** |
| **02 Справочник** | Изучать RV32I форматы R/I/S/B/U/J, кодирование инструкций, реальные примеры из BIOS | Найти инструкцию по мнемонике и посмотреть битовые поля/операцию |
| **03 Карта ROM** | Сопоставить CPU-visible окно 128 КиБ с уникальным 32-КиБ периодом, проверить зеркала и CRC | Сравнить адреса `0xB0`, `0x80B0`, `0x100B0`, `0x180B0` |
| **04 Функции и строки** | Найти строки BIOS, переходы `JAL` и ссылки из машинного кода | Искать `mem_read`, `boot`, `UART`; учитывать, что границы функций определены эвристически |
| **05 CSR и UART** | Различать CPU CSR и LiteX MMIO, разобрать `uart_init()` | Использовать переход к **PC `0x47A4`**, изучить события/маски UART |
| **06 Методика и источники** | Отделить измеренное на плате от программных реконструкций | Посмотреть ограничения моделирования и первоисточники |

## Как безопасно проводить демонстрацию

1. Вкладка **01 Исследователь** → **Сброс**, начальный `PC=0`.
2. Нажмите **Шаг** и увидите переход на `0xB0`. Следите за изменениями PC и регистров; **не путайте количество шагов с тактами FPGA**.
3. Используйте кнопки контрольных адресов, в частности **Reset vector**, **Exception vector**, **Старт BIOS**, **MMIO boundary**.
4. На `0x47A4` покажите логику `uart_init`: `lw` из `0xF0003010`, подтверждение через `sw`, запись `3` в `0xF0003014` и настройка IRQ_MASK (CSR `0xBC0`).
5. При пошаговом исполнении **из начального PC=0** модель воспроизводит независимое вычислительное состояние. Простой переход интерфейса на произвольную строку ROM **не воспроизводит весь контекст вызовов и значения регистров** — это только просмотр.
6. Модель **останавливается** перед живым чтением MMIO, если значение периферии неизвестно. Это корректное ограничение, а не ошибка программы: браузер не связан с FPGA.

## Проверенные точки в прошивке

- `0x00000000`: стартовый переход с reset vector.
- `0x00000020`: exception/trap handler; **наличие обработчика в ROM не доказывает, что мы поймали реальный IRQ**.
- `0x000000B0`: инициализация исполнения BIOS.
- `0x000047A4–0x000047BC`: UART MMIO/EventManager/CPU-specific IRQ mask.
- `0x00006644`: CRC32 `F2B1F4F6` в конце полезной части BIOS.
- Окно `0x00000000–0x0001FFFF`: четыре одинаковых периода по 32 КиБ.

Дополнительные аппаратные подтверждения: [ROM aliases](ROM_ALIAS_AUDIT.md), [UART CSR](UART_CSR_HARDWARE_2026-11-07.md), [запуск нашей RV32I-программы](../../06-RV32-RAM-Diagnostics/RV32_HARDWARE_EXECUTION_PASS_2026-11-08.md).

## Что HTML не умеет

Не является FPGA bitstream, не подключается к COM25, не считывает RAM/IRQ с платы в реальном времени, не моделирует клоки, конвейер VexRiscv или физические сигналы Wishbone с точностью по тактам. Это **учебный интерпретатор машинных инструкций реального BIOS**, с честной остановкой при неизвестных входах периферии.
