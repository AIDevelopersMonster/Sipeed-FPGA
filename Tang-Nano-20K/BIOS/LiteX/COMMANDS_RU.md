# LiteX BIOS: команды консоли на нашей Tang Nano 20K

[← Справочник LiteX](README.md) · [Карта памяти](MEMORY_MAP_RU.md) · [Демонстрации](DEMO_POINTS_RU.md)

BIOS — программа, встроенная в **заводскую** систему LiteX/VexRiscv_Min на Tang Nano 20K. Управление — UART, на испытанном ПК **COM25, 115200 8N1**, приглашение `litex>`. Это **не** командная оболочка Windows/Linux. Состав команд зависит от сборки BIOS, поэтому проверяйте `help` на **своей** плате. Ниже различаются аппаратно выполненные команды и типичные возможности исходников LiteX.

## Команды, применённые в наших реальных испытаниях

| Команда | Назначение | Проверка и ограничения |
|---|---|---|
| `help` | Показать список команд текущего BIOS | Без изменения памяти; первый шаг знакомства |
| `mem_list` | Показать карту областей памяти | В нашем журнале ROM 128 КиБ, SRAM 8 КиБ, SDRAM 8 МиБ |
| `mem_read 0x000000B0 16` | Прочитать 16 байт ROM с адреса `0xB0` | Реально использовано в LAB-20.4; см. зеркала ROM |
| `mem_read 0xF0003014` | Прочитать MMIO-регистр разрешения событий UART | На плате — `03 00 00 00`; с другими MMIO осторожно |
| `mem_write 0x40010000 0xF0003437` | **Пример** записи одного слова в SDRAM | Не обзорная команда! Применять только как часть верифицированного загрузчика и только на нужной конфигурации |
| `boot 0x40010000` | Передать CPU управление программе по этому адресу | **Реально выполнено** после сверки 740/740 байт; программа не возвращает управление BIOS |
| `reboot` | Перезапустить плату/BIOS программным способом | Использовано в раннем журнале загрузки; не использовать во время выполнения RAM-программы |

**Важное предупреждение:** `mem_read` — не универсально безвредная операция: у MMIO-регистров чтение может иметь побочные эффекты. `mem_write` может изменить аппаратные регистры, RAM или память другого назначения. В этой лаборатории запись разрешена **только** в известную SDRAM через проверенный сценарий LAB-20.6. Никаких операций с конфигурационной Flash.

## Примеры: как воспроизвести безопасные наблюдения

### 1. Проверить BIOS

```text
litex> help
litex> mem_list
```

Получите список команд **вашей** версии BIOS и карту адресов. Не путайте объём **адресного пространства** 4 ГиБ с физической памятью 8 МиБ.

### 2. Посмотреть зеркалирование ROM

```text
litex> mem_read 0x000000B0 16
litex> mem_read 0x000080B0 16
litex> mem_read 0x000100B0 16
litex> mem_read 0x000180B0 16
```

На нашем экземпляре все четыре фрагмента совпали. Это независимое подтверждение периода `0x8000` в CPU-visible окне ROM. **Не** является доказательством числа физических BRAM-блоков.

### 3. Посмотреть UART без записи в регистры

```text
litex> mem_read 0xF0003004
litex> mem_read 0xF0003008
litex> mem_read 0xF000300C
litex> mem_read 0xF0003010
litex> mem_read 0xF0003014
litex> mem_read 0xF0003018
litex> mem_read 0xF000301C
```

Сопоставление адресов с реальными измерениями — в [LAB-20.5](../../05-UART-CSR/README.md). **Не читайте в этой демонстрации `0xF0003000` (RX/TX data)**: чтение буфера приёма потенциально меняет его состояние. Значения меняются во времени, в частности `TXEMPTY` зависит от собственной печати команды BIOS.

### 4. Запуск своей программы — отдельный эксперимент

Загрузка 740-байтного `snapshot.bin` и сверка SDRAM выполняется Windows-скриптом `upload.ps1`. Только после полного PASS в том же включении платы:

```text
litex> boot 0x40010000
```

Результат — собственный UART-отчёт и `LAB20.6 HOLD`. Для возврата нажать физический RESET. **Нельзя** выполнять `boot` по адресу непроверенной программы. Полная инструкция: [Повторение LAB-20.6](../../REPRODUCE_LAB20_6_RU.md).

## Команды, встречающиеся в исходниках LiteX, но не включённые в наш безопасный маршрут

В upstream BIOS имеются обработчики операций копирования, заполнения, проверки памяти, CRC, загрузки/запуска; детали и наличие зависят от compile-time конфигурации и версии. **Не считайте их автоматически поддерживаемыми нашим BIOS** без вывода `help`. Не публикуем для них универсальные команды запуска, поскольку они могут разрушить содержимое RAM или затронуть MMIO.

**`clear` в нашем BIOS не поддерживается.** Это проверено в отдельном сеансе. Для очистки экрана используйте возможности своего UART-терминала, не пытайтесь запускать shell-команду Windows внутри `litex>`.
