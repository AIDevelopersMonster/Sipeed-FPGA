# Tang Nano 20K — единое состояние проекта и передача между сессиями

**Состояние на 2026-11-08.** Этот файл — единая опорная точка при продолжении работы над Sipeed Tang Nano 20K. Обновлять после каждого подтверждённого результата; не полагаться на память чата и не объявлять PASS без протокола с реальной платы.

## 1. Зафиксированное назначение проекта

**Основной результат — работающая плата Tang Nano 20K как изделие и доступные другим людям примеры её применения.** Технические эксперименты с LiteX, ROM, CSR и шинами являются подэтапами, а не конечным продуктом. Вначале **закрыть уже согласованный набор из 6 проверок**, не создавая новые исследовательские ветки; затем перейти к [демонстрационным примерам](Examples/README.md), где участвуют HDMI, microSD, кнопки/LED, звук и процессор.

**Важно:** PiKoSoL — проект собственной FPGA-системы на **Tang Nano 9K**. Tang Nano 20K здесь — **заводской LiteX/VexRiscv_Min**; не смешивать названия, исходники, прошивки, страницы сайтов и статусы. Упоминания PiKoSoL в сохранённых исторических логах не исправлять задним числом.

## 3. Шесть оставшихся закрывающих проверок LiteX — без расширения

| № | Проверка | Критерий закрытия и статус на 2026-11-08 |
|---|---|---|
| 1 | **SDRAM**: шаблоны данных, обратное чтение, безопасные границы выделенной области | `PENDING`: адресный тест с исключёнными ROM/MMIO и областями BIOS. Уже подтверждены BIOS memtest 2 МиБ и образ 740/740, но весь объём 8 МиБ отдельно не тестирован |
| 2 | **Wishbone / CSR**: контролируемый путь CPU → RAM/MMIO и реакции регистров | `PENDING`: RAM read/write PASS, безопасные MMIO операции подтверждены; менять управляющие MMIO только при точно установленной карте |
| 3 | **UART IRQ**: EventManager → IRQ_MASK/mie/mstatus → trap handler → mret | `PENDING`: реальное подтверждение **входа и возврата** с ограниченным количеством прерываний и защитой от IRQ storm; `EV_PENDING=1` не считается IRQ PASS |
| 4 | **Timer / Boot**: однократный/периодический таймер, возврат/повторная загрузка, ограниченные ошибки | `PENDING`: если таймер отсутствует в конкретной заводской карте, фиксируется `NOT PRESENT IN FACTORY SOC` без перепрошивки ради этого этапа |
| 5 | **Тесты исходного LiteX**: подмножество `test_csr`, `test_wishbone`, `test_timer`, `test_stream`, `test_cpu` на историческом коммите | `PENDING`: запуск в изолированной программной среде, версия зависимостей, лог PASS/FAIL, не приравнивать Migen/RTL тесты к board PASS |
| 6 | **Browser Test Bench**: модели + просмотр настоящих протоколов и, при наличии поддерживаемой связи, безопасный read-only Web Serial | `PENDING`: ссылка доступна, понятное разделение `SIMULATION`, `SOURCE TEST` и `HARDWARE`, оператор может воспроизвести результаты |

**Правило остановки:** каждый из шести этапов закрывается `PASS`, `FAIL + documented reason` или `NOT PRESENT/NOT APPLICABLE`. Не вводить LAB-20.8, 20.9 и др. из желания подробно исследовать все внутренние блоки. Новое исследование допускается только если оно является блокирующим дефектом конкретного примера изделия.

## 4. После закрытия — только примеры применения платы

[Examples — HDMI, microSD, LED/кнопки, звук, комплексная демонстрация](Examples/README.md). Каждый пример имеет `README для пользователя`, точный образ, SHA-256, безопасный способ загрузки **в SRAM**, описание подключения, фото/видео или UART/HDMI доказательства, известные ограничения и понятную инструкцию повторения.

Разделять два класса демонстраций: (a) **независимые готовые Sipeed `.fs`** — проверяются отдельно и после смены образа уже не исполняют заводской LiteX; (b) **единый собственный SoC**, требующий интеграции и новой FPGA-сборки. Не заявлять HDMI/SD работающими совместно с нашим BIOS без построения и проверки единого образа.

## 5. Правила сохранения и безопасности

- Не переписывать и не стирать заводскую конфигурационную Flash. Сначала готовый `.fs` — временная загрузка в FPGA SRAM; проверять точный режим программатора.
- Перед любой сменой FPGA-конфигурации сохранить текущие COM/BIOS и аппаратные свидетельства. После новой конфигурации **не ожидать**, что старый BIOS продолжит работать параллельно.
- Ни бинарные образы, ни SHA-256 оригинальных опытов задним числом не изменять. Для новых сборок отдельные версии, хеши и протоколы.
- STATUS различает `SOURCE AVAILABLE`, `SIM PASS`, `BOARD PASS`, `FAIL`, `NOT TESTED`. Публикация исходников Sipeed сама по себе не равна нашему board PASS.
- Все тесты писать с ограничением времени, итераций и адресного диапазона; сомнительные MMIO и microSD запись исключить из первого демонстрационного этапа.
- Результаты оставлять в GitHub **после каждого испытания**, чтобы можно было продолжить проект в новом чате или с другим исполнителем.
