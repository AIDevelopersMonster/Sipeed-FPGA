# PiKoSoL-20K / P20-SHELL-01 v0.1.0 — первый переносимый слой

**Статус:** `HOST_C_TEST_PASS / RV32I_CROSS_BUILD_PASS / BOARD_NOT_TESTED`.
Это *новая* программа для VexRiscv/LiteX на Tang Nano 20K, а не PicoRV32 ROM и не новый FPGA-битстрим. Исходная EX20-05.16 и её проверенная FPGA-конфигурация **не изменяются**.

Источники:
- 9K, **экспериментальная** LAB-04.3.2 v0.2.0-alpha: `01-PicoRV32/lab04/README_v0200_LAB0432_RU.md`; аппаратно доказана **предшествующая v0.1.8b1**, не v0.2.0-alpha.
- 20K, EX20-05.16: `Tang-Nano-20K/Examples/EX20-05-CPU-HDMI/EX20-05-16_RELEASE.md`; подтверждены VexRiscv, LiteX UART BIOS, V201 Wishbone и один прямоугольник HDMI.

## Реализовано в этой версии

- Независимая от процессора C99-оболочка с внедряемым I/O API и адаптером для LiteX CSR UART (115200 8N1).
- `HELP`, `INFO`, `STATUS`, `GFX`, `TERM`, `OBJ A|B`, `MOVE I|J|K|L`, `COLOR R|G|U|W`, `SIZE +/-`, `BG RRGGBB`, `LED ?`.
- Строковый ввод до 47 ASCII, регистронезависимые команды, CR/LF/CRLF, Backspace/DEL, Ctrl-P для одной предыдущей команды, ограничения координат 1280x720.
- Два **логических** объекта A/B; существующее EX20-05.16 отображает **только выбранный**. Никакой второй фигуры, контура и checkerboard аппаратно пока нет.
- Запись в реально существующий V201 Wishbone MMIO `0xB1000000`, только после проверки сигнатуры `0x56323031` (V201). Перед каждой пачкой — ожидание свободного STATUS, затем 4 регистра и COMMIT, ожидание ACK/освобождения BUSY.
- `TERM` **пока не видеотерминал**: скрывает прямоугольник (`WH=0`) и оставляет UART-оболочку. Для букв на HDMI нужен новый, отдельно проверяемый RTL. `LED ?` сообщает, что EX20-05.16 не подключает LED; в неизвестные регистры не пишет.
- Первое включение только читает ID и фон: никаких видеозаписей до команды пользователя.

## Сборка и тесты на ПК

```bash
./tools/test_host.sh
# Следующая строка — ПРИМЕР. UART_BASE=0xF0003000 доказан для LAB-20.6,
# но ОБЯЗАТЕЛЬНО проверьте EX20-05.16 csr.csv перед применением на плате.
./tools/build_rv32.sh 0xF0003000
```

Понадобятся `clang`, `ld.lld`, `llvm-objcopy`, `llvm-objdump`, Python 3, обычный C compiler с ASan/UBSan. Результат: `build/pikosol20k.elf`, `.bin`, `.map`, дизассемблирование, SHA-256 и **только** список `build/load_mem_write_only.txt` для SDRAM. Скрипт **не открывает COM**, не вызывает `boot`, Gowin, JTAG или Flash.

Скрипт ELF рассчитан на **предполагаемую** SDRAM `0x40010000..0x4001BFFF`, стек `0x4001C000..0x4001FFFF`. Это НЕ подтверждение карты памяти EX20-05.16. Не загружайте бинарник, пока не проверены конкретная версия SoC, `csr.csv`, UART CSR и SDRAM. Параметр UART_BASE обязателен; VIDEO_BASE защищён сигнатурой, но отсутствие периферии всё равно может вызвать CPU trap при чтении.

Выполнение `boot 0x40010000` передаёт управление программе до физического RESET. **Не выполнять до полной проверки загруженных байт и карты памяти.** Проверенная ранее процедура LAB-20.6 относится к **другому, заводскому образу LiteX**; сама по себе она не доказывает, что новый EX20-05.16 использует идентичную карту.

## Тестовый протокол

Нативные тесты: реальные функции C с mock MMIO V201, проверяющие команды, CRLF, обратный ввод, историю, оба программных объекта, геометрические границы, защиту ID, запрет записи при BUSY, ACK timeout. Дополнительные Python-тесты проверяют генерацию SDRAM-команд и отсутствие операций `boot/Flash`. Целевая кросс-сборка проверяет freestanding/RV32I-совместимость, **не физическое выполнение**.

Подробности: [матрица переноса](docs/PORTING_MATRIX_RU.md), [проект TERM](docs/TERM_PLAN_RU.md), [ступени аппаратной приёмки](docs/BOARD_ACCEPTANCE_RU.md).

**Точки безопасности:** не трогать `EX20-05-CPU-HDMI/build/`, доказанный `project.fs`, Gowin-проект и Flash; эксперимент хранить отдельно. Никаких новых HDL-модулей к действующему HDMI в этом пакете не подключено.

## Дополнение 10.11.2026 — P20-SHELL-01 v0.2.0: защищённая аппаратная приёмка

**Стадия:** `HOST_C_TEST_PASS / PYTHON_LOADER_TEST_PASS / RV32I_BUILD_PASS / BOARD_NOT_TESTED`.
В исходную оболочку, рабочий `EX20-05.16` и HDMI-RTL изменений нет.

Добавлены независимые от FPGA инструменты:

- `tools/soc_map_guard.py` — проверяет **фактический локальный** `csr.csv` EX20-05.16:
  точные UART CSR, память SDRAM для кода/стека и видеорегион V201;
  неполную или несоответствующую карту отвергает.
- `tools/write_build_manifest.py` — записывает хеш, UART_BASE и адрес загрузки вместе с
  конкретной RV32I сборкой; при несовпадении с реальным `csr.csv` загрузчик отказывает.
- `tools/board_accept.py` — **по умолчанию dry-run**; под флагами `--probe`,
  `--upload`, `--verify-only` открывает COM25; проверяет V201 ID/version/BUSY;
  пишет только SDRAM с полным readback; умеет перейти к `boot` **только**
  с двумя флагами `--boot --confirm-boot`. Нужен `pyserial` исключительно для живых COM-операций.
- `tests/test_soc_map_guard.py`, `tests/test_board_accept.py`, `tests/test_board_cli.py`
  — позитивные и негативные тесты реального Python-кода c эмулятором LiteX,
  включая сбой идентификации V201, несоответствие карты, повреждённый readback,
  неверный SHA256 и запрет не-SDRAM записей.

**Текущая проверка:** 21 Python-тест PASS + 8 групп тестов C PASS.
Это *не* аппаратная приёмка. Полная инструкция Windows/COM25 и статусы:
[BOARD_ACCEPTANCE_V02_RU.md](docs/BOARD_ACCEPTANCE_V02_RU.md).

Ничего не запускается автоматически. Экспериментальный `.bin` остаётся
SDRAM-приложением, а не новым битстримом. `TERM` по-прежнему UART-only.
