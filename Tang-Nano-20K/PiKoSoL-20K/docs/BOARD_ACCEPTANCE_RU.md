# P20-SHELL-01: последовательность аппаратной приёмки (не выполнена)

## Gate 0 — неизменность эталона

Из EX20-05.16 RELEASE известен board-demonstrated `.fs` SHA-256:
`78AE2B41ACEF049F4A14AC63F74A6E595C72DABAE7EF072C142135A846F38015`.
Этот бинарник хранится у оператора; он **не находится** в данном пакете. Проверить его SHA-256 и provenance независимо. **Никаких `programmer_cli`, JTAG, Flash, FPGA build в этой приёмке нет.**

## Gate 1 — офлайновое ПО

В отдельном checkout: `./tools/test_host.sh`; `./tools/build_rv32.sh <UART_BASE_из_csr.csv>`. Зафиксировать SHA-256 `.bin`, размеры, linker map, дизассемблирование RV32I и исходную ветку. `HOST PASS` и `RV32 BUILD PASS` **не заменяют** `BOARD PASS`.

## Gate 2 — идентичность уже запущенного EX20-05.16

Только COM25 115200 8N1 с LiteX BIOS: `litex>`; выполнить **чтение без записи**:

```text
mem_read 0xB1000000 4
mem_read 0xB1000014 4
```

Первое должно вывести байты `31 30 32 56` (слово 0x56323031, V201), второе статус с нулевым BUSY. Если нет подписи, окно и адреса неизвестны или BIOS не совпадает — **STOP: NO MMIO WRITES/NO BOOT**.

Отдельно сравнить `csr.csv` именно построенного EX20-05.16: `uart` base, ширину/смещения LiteX UART CSR, SDRAM origin/length (`0x40010000` должен попадать внутрь реальной SDRAM), отсутствие конфликтов с V201. Положительные результаты LAB-20.6 на заводском BIOS не доказывают эту карту. Если реальная карта не совпадает — поменять параметры линкера/сборки **на ПК**, не работать методом перебора адресов на плате.

## Gate 3 — только SDRAM, со сверкой каждого байта

Выход `build/load_mem_write_only.txt` содержит **только** `mem_write` начиная с 0x40010000. Он не вызывает записи автоматически. Для переноса потребуется проверенный процесс загрузки в SDRAM с чтением `mem_read` и побайтовой сверкой **всего образа**, включая последнюю неполную четверку. Сохранить лог и SHA-256. Не запускать `boot`, пока `SDRAM_READBACK_PASS` не получен. Не копировать старый `upload.ps1` LAB-20.6 без пересмотра размера, адресов, manifest и регрессионных тестов. В `build/` нет Flash-образа.

## Gate 4 — явный экспериментальный запуск (оператор)

Только после Gate 2+3 и при открытом терминале:

```text
litex> boot 0x40010000
```

Ожидается `PiKoSoL-20K shell v0.1`, `VIDEO ID=0x56323031 OK`, `PiKoSoL20K>`; приглашение BIOS не возвращается до аппаратного RESET.

Команды и осмотр HDMI:

```text
HELP
INFO
STATUS
GFX
MOVE L
COLOR U
OBJ B
MOVE I
SIZE +
BG 102040
TERM
LED ?
GFX
```

Должны реально меняться координаты/цвет **одного** прямоугольника, а TERM скрывать его, но **не печатать текст на HDMI**. Наблюдать UART-эхо, CRLF, Backspace, Ctrl-P, отсутствие trap. `LED ?` обязан сообщить «not mapped» без попытки писать LED. Сохранить фото/видео HDMI, UART лог, фото платы и хеш бинарника.

## Gate 5 — восстановление

Физический RESET, убедиться, что старый LiteX BIOS и видео подпись возвращаются. Если UART не отвечает, видеорегистры не меняются, пропал HDMI, в статусе BUSY=1 после таймаута или имеются неизвестные CSR — **не программировать Flash и не искать случайные адреса на плате**; собрать лог, вывести причину, вернуть проверенный SRAM образ при необходимости по отдельной проверенной процедуре.

## Формулировка результатов

`P20-SHELL-01 HOST_C_TEST_PASS / RV32I_BUILD_PASS` допустимо после ПК-тестов; `P20-SHELL-01 SDRAM_READBACK_PASS` только по реальному блочному readback; `P20-SHELL-01 BOARD_SHELL_PASS` только после явного выполнения команды boot, видео и UART испытаний. `TERM-HDMI PASS` **недоступен**, пока нет новой RTL-сборки и её приёмки.
