# LAB-20.5 — UART и CSR: что проверено на железе

[Главная страница](../README.md) · [ROM Explorer](../04-ROM-Explorer/README.md) · [Собственная программа](../06-RV32-RAM-Diagnostics/README.md)

Есть **два вида CSR**: регистры ядра RISC-V (`mstatus`, `mie`, `mtvec`, пользовательская маска IRQ `0xBC0`) доступны через инструкции `csrr*`; регистры периферии LiteX доступны через `lw/sw` и отображены в память по адресам около `0xF0003000`.

Через команду BIOS `mem_read` непосредственно измерены семь UART-регистров (последовательно, не одновременно): `txfull=0`, `rxempty=1`, `ev_status=1`, `ev_pending=0`, `ev_enable=3`, `txempty=0`, `rxfull=0`.

Почему `txempty=0` мог быть вызван самим методом: BIOS печатает `Memory dump:` через тот же UART **до чтения** значения FIFO. Мы написали независимую [RAM-only программу](../06-RV32-RAM-Diagnostics/README.md) и увидели на плате `TXEMPTY=1` до собственной печати и `0` после неё.
