# KonSol Cross-CPU Terminal Demos v0.1

**Сборник демонстрационных программ для разных процессоров — БЕЗ BASIC.** Исходники написаны на C90, ориентированы на обычный текстовый/ANSI-терминал (UART, USB CDC, системная консоль). Можно использовать одинаковые алгоритмы на разных CPU, меняя только платформенный ввод/вывод.

**Статус:** компиляция и запуск на ПК проверены. **Для конкретных FPGA-процессоров порты UART, CRT/startup, карта памяти и загрузчик ещё не подготовлены; аппаратный запуск этих C-программ не заявляется.** Это независимый от прежней BASIC-лаборатории сборник.

## Содержание

| № | Программа | Демонстрация | Техническая идея |
|---|---|---|---|
| 1 | **Mandelbrot** | Цветной фрактал 68×24 | Комплексная динамика, **фиксированная точка Q10**, без `float` |
| 2 | **Conway Life** | Игра «Жизнь», 12 поколений | Клеточный автомат, два символьных буфера |
| 3 | **Maze BFS** | Генерация лабиринта, найденный кратчайший путь | DFS + BFS, целочисленные массивы |
| 4 | **Bubble Sort** | Движущиеся цветные столбцы и счёт операций | Сортировка 32 чисел, сравнения и перестановки |
| 5 | **3D Cube** | 16 кадров вращающегося каркаса | Целочисленные матрицы поворота и алгоритм Брезенхема |
| 6 | **Ulam Spiral** | Спираль простых чисел 31×31 | Теория чисел, проверка простоты |
| 7 | **CPU Info + CRC32** | Размеры типов, порядок байтов, контрольная сумма | Детерминированная сверка на разных CPU |

В интерактивных анимациях **каждый следующий кадр по Enter**. Это намеренно: нет зависимости от скорости UART, частоты процессора, таймера, `sleep` или `clock()`. Клавиша `8` включает и выключает ANSI-цвет. Код **не использует `malloc`, плавающую точку или системные файлы**.

## Запуск на Windows для предварительного просмотра

Нужен GCC (MinGW/MSYS2) или Clang в `PATH`. В проводнике можно открыть `Build_Windows.cmd`. Он соберёт и запустит `demos.exe`. В обычной консоли цветовые ANSI-коды работают в современных Windows Terminal и других ANSI-совместимых терминалах.

В PowerShell, если компилятор уже установлен:

```powershell
.\Build_Windows.cmd
```

Один пример без цвета — без интерактивного меню:

```powershell
.\demos.exe --plain --demo 1
```

Все семь без пауз (длинный вывод):

```powershell
.\demos.exe --plain --all
```

На Linux/macOS (с `cc`/`gcc`): `make && ./demos`. Для быстрой сверки: `make quick-check`.

## Как запускать на других процессорах FPGA

1. Скомпилируйте файлы из `src/` **без** `platform_stdio.c` на выбранном CPU; определите `DEMO_FREESTANDING`.
2. Реализуйте **только две функции**: `void platform_putc(int)` и `int platform_getc(void)` в аппаратном адаптере UART/консоли. Черновой шаблон: [`ports/platform_uart_TEMPLATE.c`](ports/platform_uart_TEMPLATE.c).
3. Предоставьте стартовый код C, стек, инициализацию `.data`/`.bss`, карту памяти (включая статические буферы), программу загрузки и терминал.
4. Если на плате есть стандартная библиотека C с `putchar()`/`getchar()`, можно вместо адаптера использовать `platform_stdio.c`; тогда не определять `DEMO_FREESTANDING`, либо исключить `platform_host_init()` через собственный `main`.
5. Для полного меню требуется **UART RX**; при наличии только UART TX можно сделать безвводовый запуск одной функции `demo_mandel()`/`demo_ulam()` в своем `main`.

**Важно по нашим ядрам:**

- **Tang Nano 9K / ранний PicoRV32 LAB-02**: ROM всего 1 КиБ, нет C runtime и UART RX. Эта прошивка **не может напрямую** запустить сборник. Нужна другая конфигурация SoC с RAM, кодом запуска и UART.
- **Tang Nano 20K / заводской LiteX VexRiscv**: есть SDRAM, UART и BIOS, но нужен отдельный порт, загрузка C ELF/бинарного образа и согласование с BIOS. Это **не** готовый образ для команды `boot`.
- **Другие ядра (PicoRV32, VexRiscv, NEORV32 и т. д.)**: возможно при наличии подходящей платформенной среды и достаточной RAM. Наличие ядра само по себе недостаточно.
- Z80/BBC BASIC здесь **не используется**. Для CP/Mish Z80 можно будет изучить порт компилятором C с собственным библиотечным слоем, но это отдельная задача.

## Соглашение об интерфейсе

```c
void platform_putc(int ch); /* передать один 8-битный символ на UART */
int  platform_getc(void);     /* блокирующее чтение; 0..255 либо -1 при EOF */
```

Остальной код сам строит символьные кадры, цвета `ESC[...m`, смену экрана `ESC[2J` и `ESC[H`, меню и арифметику. Программы предполагают **8-битные байты**, 16-битный или более широкий `int`, **не менее 32 бит у `long`**, согласованный компилятор C90 и достаточный объём RAM для статических массивов (несколько килобайт (вместе со стеком обычно больше 8 КиБ)).

## Смысл серии

Один и тот же набор численных и алгоритмических задач запустить на нескольких процессорах — и затем **по измеряемым данным**, без заранее придуманных цифр, сравнить размер программы, RAM, скорость кадров, число операций, качество терминального вывода. Демонстрация №7 поможет удостовериться, что на разных архитектурах совпадает CRC32(`123456789`) = `CBF43926`.

**Ближайшая практическая цель:** выбрать первое RISC-V окружение с рабочим C runtime и UART RX/TX и перенести весь сборник без изменения алгоритмов.
