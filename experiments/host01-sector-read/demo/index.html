01. Сектор — минимальный адресуемый «кирпичик» HOST-01

Блоковый адрес LBA

Представьте диск как очень длинную линейку из одинаковых блоков. Каждый блок имеет номер — LBA (Logical Block Address). В нашем SDHC SPI-контроллере команда CMD17 читает один блок 512 байт.

LBA = floor(1025 / 512) = 2

Сектора вокруг выбранного адреса

Выбранный сектор и смещение вычисляются автоматически.

Почему именно блоки?

Блочный интерфейс позволяет адресовать данные единообразно и передавать их порциями фиксированного размера. Это упрощает контроллер, буферизацию, проверку ошибок и файловую систему.

Важно: сектор — минимальная единица нашего интерфейса блочного чтения, а не минимальный физический элемент флеш-памяти и не обязательно единица стирания. Внутри microSD контроллер управляет страницами NAND, блоками стирания и износом.

logical_byte_address = LBA × 512 + offset LBA = floor(byte_address / 512) offset = byte_address % 512 Например, байт 1025 → сектор 2, смещение 1.

На иных накопителях логический сектор может иметь размер 4096 байт. Здесь 512 — размер, непосредственно проверенный для SDHC и FAT32 HOST-01.

02. Один диск — несколько слоёв смысла

Адреса нашей карты

Байты MBR, FAT и файлов физически лежат в одной линейной последовательности LBA. Программа интерпретирует разные диапазоны по-разному. Нажмите любую область:

Выберите область карты.
LBA данных = начало раздела + резерв + две FAT

Блоки на схеме нарисованы не в масштабе: длинная область данных иначе заняла бы почти весь экран. Реальные размеры указаны номерами секторов.

MBR ≠ файловая система

MBR сообщает, где начинается раздел и сколько LBA он занимает. Само содержимое файлов находится в другом месте.

VBR ≠ MBR

VBR лежит в начале раздела и задаёт параметры конкретной FAT32: размеры секторов, кластеров, FAT и адрес корневого каталога.

FAT ≠ содержимое файла

Таблица FAT связывает номера кластеров. Фактические байты файла записаны в области данных.

03. MBR и «магические» байты 55 AA

LBA 0 · 512 байт

Master Boot Record

В классической схеме MBR первый сектор носителя делится на области: загрузочный код или служебные данные в начале, четыре 16-байтовые записи разделов с позиции 446 и двухбайтовую сигнатуру в конце.

0…445код / служебное
446…5094 × 16 Б · разделы
510–51155 AA
offset 51055HEX = 85 DEC
offset 511AAHEX = 170 DEC
Байты по порядку: 55 AA Как uint16 little-endian: 0xAA55 В десятичной системе: 85 170 По битам: 01010101 10101010

Это маркер формата, а не криптографическая подпись и не CRC: присутствие 55 AA само по себе не доказывает исправность диска. Такие же два байта встретились в конце VBR.

В каждой записи 16 байт: флаг загрузки, CHS-поля, тип, стартовый LBA и число секторов. Поля старого CHS-адресования в современных задачах обычно второстепенны.

04. FAT32: почему «32» и как вычисляется адрес файла

VBR: LBA 64

FAT = File Allocation Table, таблица размещения файлов. Число 32 — размер одной записи FAT в битах. Из 32 бит для индекса кластера FAT32 используются 28; старшие четыре зарезервированы.

FAT1212 бит
на запись таблицы
FAT1616 бит
на запись таблицы
FAT3232 бита
28 бит адреса кластера

Почему именно FAT32 на этой карте?

Не потому, что microSD «обязана быть FAT32». Наша карта отформатирована в FAT32: это следует из полей её VBR и числа кластеров. Другие карты могут использовать FAT16 или exFAT. FAT32 проста и совместима со многими микроконтроллерами и встроенными устройствами.

Файловая система FAT32 выделяет место кластерами, а контроллер microSD читает данные секторами. Это разные уровни.

Подтверждённая по логу сигнатура VBR: 55 AA.

BPB — параметры тома из VBR

Источник: первые 64 байта из HOST-01

Формулы FAT32

Модель цепочки кластеров — учебный пример, не содержимое карты

Файл может быть фрагментирован: его кластеры не обязаны идти друг за другом. В FAT32 запись кластера указывает следующий кластер цепочки или специальный признак конца.

05. Каталоги — как 32-байтовые записи превращаются в имена

ROOT: LBA 17472

Корневой каталог — тоже данные

В FAT32 корень начинается с кластера, номер которого хранится в BPB (здесь кластер 2). Каталог состоит из записей по 32 байта. В секторе 512 байт помещается 16 записей.

Обычная запись 8.3 (32 байта) 0…10 имя и расширение (11 байт) 11 атрибуты 20…21 старшие 16 бит первого кластера 26…27 младшие 16 бит первого кластера 28…31 размер файла, байт LFN: attr = 0x0F Несколько LFN-записей + короткое имя → длинное Unicode-имя

В показанных HOST-01 первых 64 байтах каталога видны две LFN-записи с номерами 42 и 01. Их имя соответствует System Volume Information. Полную проверку сцепления с короткой записью можно выполнить, загрузив root.bin.

Кластер ≠ сектор

Файл занимает кластер или цепочку кластеров. Для чтения файла программа:

1. Находит запись в каталоге. 2. Узнаёт первый кластер и размер. 3. Читает 64 сектора этого кластера. 4. Узнаёт следующий номер из FAT. 5. Продолжает до EOF / конца размера.

Если файл имеет размер 100 байт, при выделении 32 КиБ под кластер файловая система всё равно хранит полезными только 100 байт. Остальное — внутреннее неиспользованное место последнего кластера.

Байты 55 AA — это…

Основание демонстрации: аппаратные журналы HOST-01: LBA 0, 64, 17472 по 512 байт, CRC PASS и сигнатуры 55 AA у MBR/VBR. Значения из первых 64 байт и проверенные последние 2 байта показаны до выбора файлов; остальные байты неизвестны. Макет цепочки кластеров отдельно отмечен как учебный.

Справочные источники: UEFI — структура MBR, разделы и 55 AA; Espressif — FAT12/16/32, сектора и кластеры; Microsoft — обозначения FAT. Они не нужны для автономной работы этой страницы.
