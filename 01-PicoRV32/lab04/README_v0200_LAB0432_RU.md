# LAB-04.3.2 — PiKoSoL Interactive Shell (v0.2.0-alpha)

Дата: 2026-10-23. Экспериментальная ветка поверх **аппаратно проверенной v0.1.8b1**. Это **не** свидетельство прохождения Icarus/Gowin/STA/board для v0.2.0: реальные RTL/Gowin/плата ожидаются.

## Назначение

Перевод PiKoSoL от набора однобуквенных UART-команд к выполнению строковых команд **процессором PicoRV32**, не имитацией на ПК. На HDMI два режима:

* **TERM**, режим по умолчанию: терминал занимает центральный экран; на видеослое — кольцевая память 32 × 76 ASCII, одновременно до 29 видимых строк, прокрутка, ввод/ответы PicoRV32. Плавающие квадраты A/B скрыты под непрозрачным фоном (их состояние сохранено).
* **GFX**: центральная графическая область **x=32…448, y=112…344** с объектами A/B, справа состояние, внизу LED HUD и четыре строки терминала. Фигуры имеют исходные координаты A=(100,180), B=(280,212); их перемещение и ширина ограничены пределами области.

Команды вводятся в COM10 с **Enter**. В ROM работает конечный разборщик ASCII, редактор строки на 47 символов, Backspace/DEL и история *одной* команды по Ctrl-P. Вывод на COM10 сопровождается эхо от PicoRV32; видео UART-путь принимает **только TX от CPU**, чтобы символы не удваивались. Символы управления режимом `SO` (0x0E), `SI` (0x0F) и `FF` (0x0C) используются видеослоем; некоторые программы для COM могут их интерпретировать по-своему. В MobaXterm настройка `Implicit CR in every LF` больше не обязательна для новых ответов: прошивка выдаёт CR+LF.

## Команды

| Команда | Действие |
|---|---|
| `HELP`, `INFO`, `MEM`, `STATUS` | Справка, сведения о CPU, ROM/RAM, состояние LED |
| `LED 0`…`LED 6`, `LED ?` | Количество активных LED и чтение маски |
| `GFX` | Переключить HDMI в графическую область |
| `TERM` | Вернуться в полноэкранный текстовый режим |
| `CLS` | Очистить видеопамять терминала (не очищает историю ПК) |
| `OBJ A`, `OBJ B` | Выбрать объект |
| `MOVE I/J/K/L` | Вверх/влево/вниз/вправо, шаг 8 пикселей |
| `COLOR R/G/U/W` | Красный/зелёный/синий/белый |
| `SIZE +`, `SIZE -` | Ширина ±8, с ограничением canvas |
| `PANEL` | Вывести ASCII-панель координат и LED |
| `KEYS` | **В режиме GFX** включить однобуквенное управление без Enter |
| `Ctrl-P` | Подставить предыдущую команду (только если строка пуста) |
| `Backspace` / `DEL` | Стереть последний символ из буфера и экрана |

**Режим `KEYS`:** после `GFX`+Enter и `KEYS`+Enter посылайте `i/j/k/l` для движения, `A/B` для выбора объекта, `R/G/U/W` для цвета, `+/-` для ширины, `X/O/K` для изменения режима. Сразу реагирует **без Enter**; `T` или `t` немедленно возвращает в TERM и включает обычный строковый ввод. Для проверки можно набрать `jjjkkkT`.

Старые однобуквенные команды также разрешены в обычном режиме, но **требуют Enter**. Это предотвращает случайное выполнение отдельных символов во время набора строки. До входа в `KEYS` непосредственное `jjjj` без Enter не двигает фигуры.

## Память и сохранённые интерфейсы

* Синхронная программная BRAM: 4096 × 32 бит = 16 КиБ, адрес `0x00000000..0x00003FFF`. Фактическая сборка содержит меньше 4096 инструкций, остальное NOP.
* Программная BRAM для данных: 256 × 32 бит = 1 КиБ, адрес `0x00004000..0x000043FF`, используется под ввод/историю.
* HDMI-терминал: кольцевая память 32 × 76 символов; чтение и запись в пиксельном домене, без CPU random-access к этой памяти.
* MMIO LED `0x20000000`; UART TX/RX/status `0x20000010`, `0x20000018`, `0x2000001C`; видео-регистры `0x20000100..0x2000013C` сохранены.
* UART 115200 8N1; Gowin PLL, TMDS/HDMI PHY, graphics CDC 28 бит, UART byte CDC 8 бит + req/ack не изменялись.
* Со стороны видео CPU+HDMI прежний пассивный захват RX отключён, чтобы не дублировать программное эхо; Smoke-версия остаётся в прежнем режиме (`HOST_TAP_ENABLE=1` по умолчанию).

## Приёмка — строго по ступеням

1. `python tools/verify_kit.py` (SHA-256, проверка ROM).
2. `python tests/test_lab04_model.py` и `tools/test_lab04.ps1 -ModelOnly` (действительные инструкции ROM в Python CPU-модели; **не RTL**).
3. `tools/test_lab04.ps1` с Icarus: legacy video/CDC, новый терминал, **реальный PicoRV32** + синхронные ROM/RAM + UART.
4. `tools/build_lab04.ps1 -Mode CPU` через Gowin CLI в отдельный каталог сборки. Никаких изменений LAB-03.
5. `tools/check_sta_v018b.py` на **новом** `*_tr_content.html` + `gowin_cli.log`: 28 графических CDC-путей + 8 UART-путей + req/ack, 15 SDC max delays, положительные setup/hold/recovery/removal. При нехватке BSRAM/LUT, RP0006, отсутствующих маршрутах, отрицательных slack — **DO NOT PROGRAM**.
6. Только затем `tools/program_lab04_sram.ps1 -Bitstream ... -Program`, операция Gowin **2**, только volatile SRAM, Flash не трогать.
7. `tools/test_lab0432_board.ps1 -PortName COM10`, реальный UART+HDMI с ручной проверкой, включая живое управление `jjjkkk`.

## Известные ограничения / не-заявления

* Это учебная интерактивная оболочка **без файловой системы, процессов, прерываний, сетевого стека и полноценной ОС**.
* История состоит из **одной предыдущей команды**, редактирование — только Backspace; курсорные стрелки ANSI пока не разобраны.
* CLI отображает ASCII; русские символы не поддерживаются шрифтом 8×12.
* Рендеринг пикселей и ресурсы Gowin новой версии не проверены до пользовательской сборки. Контрактные проверки не заменяют функциональные и аппаратные испытания.
* Стационарная панель статуса версии v0.1.8b сохраняется; графические координаты ограничены программой CPU, а не аппаратной маской graphics OSD.
* Для работы в режиме GFX+KEYS пользователь должен знать управляющую последовательность; немедленный возврат — `T`.

**Контрольная версия**: LAB-04.3.1 v0.1.8b1 с подтверждённой FPGA/HDMI/UART функциональностью. До прохождения всего цикла её нельзя объявлять заменённой.
