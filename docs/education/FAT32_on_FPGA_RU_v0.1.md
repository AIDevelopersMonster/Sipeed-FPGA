# FAT32 непосредственно на FPGA: от MBR к аппаратному автомату
**Инженерная статья · русский язык · проект SD-03 · черновик v0.1**

## Постановка задачи

Исходная лаборатория SD-02.1 на Tang Nano 9K доказала возможность прочитать четыре произвольных SDHC-сектора (LBA 0, 1, 2048, 65541) через SPI без PicoRV32; оператор получил `SD02 PASS`. Но ни разделы, ни файловая система на карте не разбирались.

SD-03 не должна делать сразу FAT32-контроллер чтения файлов. Её цель — последовательно доказать: **(1)** корректное распознавание структуры MBR; **(2)** чтение boot-sector выбранного раздела; **(3)** валидацию BPB и адресов FAT/data; **(4)** только затем переход к каталогам.

## Аппаратная архитектура

```text
             CMD17 / sector DMA
  microSD <-- SPI master <--- SDHC reader
                               |
                         BSRAM 512 bytes
                               |
                      byte address / data
                               v
                      MBR parser (SD-03.1)
                         |           |
                FAT32 candidate    reject
                         |
                     next CMD17
                         |
                    BPB validator (SD-03.2)
                         |
                FAT/data/root LBA map
                         |
                 FAT chain reader (SD-04)
```

Состояния автомата отделяют физическую успешность чтения блока от логической корректности формата. Слово `candidate` принципиально: MBR сообщает тип раздела, но не сертифицирует реальное содержимое файловой системы.

## Уже реализовано: SD-03.1

В лабораторном каталоге `boards/tang-nano-9k/experiments/sd-mbr-fat32` подготовлен Verilog-2005 модуль `sd03_mbr_parser`, принимающий поток из 512 байтов с индексом и сигналом валидности. Он извлекает тип раздела, начальный LBA и длину раздела из little-endian полей. При некорректной сигнатуре или защитном GPT выдаёт явный код состояния. Это **изолированный RTL-модуль**, ещё не интегрированный с SD-контроллером или проверенный на плате.

Тестбенч моделирует FAT32-кандидат с началом LBA 2048, отсутствие FAT32, защитный GPT, неверную сигнатуру и пустую запись. CI — отдельный контроль, результаты которого следует фиксировать независимо от аппаратных испытаний SD-02.

## Первое соединение модулей: SD-03.3

Добавлен `sd03_volume_scanner.v`: аппаратный планировщик принимает интерфейс чтения SD-02 (`start/LBA/done/error`) и последовательно получает 512 байтов через синхронный `peek_data`. На LBA0 он параллельно проверяет MBR и BPB; если найден кандидат раздела FAT32, направляет новый запрос CMD17 по адресу VBR. Для superfloppy не требуется второе чтение. Формат GPT не подменяется FAT32.

Интеграционный тестбенч `tb_sd03_volume_scanner.v` теперь **прошёл CI**: последовательный запрос LBA0→VBR, superfloppy, защитный GPT и отказ при некорректном BPB. [Протокол GitHub Actions](https://github.com/AIDevelopersMonster/Sipeed-FPGA/actions/runs/40068297667). Это программная модель синхронного BSRAM-интерфейса, а не свидетельство работы SD-03 на физической карте. Для полноценной аппаратной приёмки требуются top с UART, Gowin PnR/STA и испытания на Tang Nano 9K.

## Что предстоит сделать

**SD-03.2:** мост BSRAM SD-02 → MBR parser и чтение второго сектора по выбранному LBA.

**SD-03.3:** BPB validator, контроль байтов на сектор, размера кластера, FAT32-специфичных полей, границ раздела и вычислений с расширенной разрядностью. Отдельный сценарий для superfloppy, если LBA0 сам является корректным VBR.

**SD-03.4:** независимые тестбенчи позитивных/негативных структур, сравнение с секторным образом известного происхождения, затем Gowin PnR/STA и реальная SD-карта в режиме только чтения.

## Экономика FPGA

Простая реализация использует один буфер BSRAM на 512 байтов и последовательный FSM, а не хранение всего раздела в FPGA. Для FAT32 таблицы и каталоги читаются по требованию; потребность в дополнительной RAM зависит от кэша. Реальные LUT/FF/BSRAM/Fmax необходимо измерить для конкретной сборки; переносить цифры SD-02 на SD-03 нельзя.

## Научная дисциплина

- Нельзя объявлять FAT32 по последним байтам `55 AA`.
- Нельзя называть результат тестбенча аппаратной приёмкой.
- Нельзя заявлять работу с файлами до чтения каталога и цепочки кластеров.
- Отрицательные случаи и неподдерживаемые форматы — полезные воспроизводимые результаты.

**Статус:** каркас инженерной статьи и первая RTL-заготовка. Для опубликованной технической статьи потребуются реальные CI-логи SD-03, схемы, замеры PnR/STA, результат аппаратного испытания и ссылки на версию исходников.

## SD-03.4 — самостоятельная аппаратная сборка

Подготовлен аппаратный `sd03_mbr_fat32_probe_top.v`, связывающий автономный SDHC-чтение с парсерами MBR, FAT32 BPB и выходом UART 115200 8N1. Состояния различают корректный том FAT32 в разделе MBR, FAT32 без MBR (superfloppy), защитный GPT, отсутствие распознанной FAT32, неверный BPB и аппаратную ошибку CMD17/CRC.

На этом этапе **успешность RTL-компиляции и симуляции ещё не означает аппаратный PASS**. Полноценные результаты Gowin PnR/STA, контроль SHA-256 `.fs`, распознавание реальной карты и сохранение точного UART-протокола составляют следующий независимый акт приёмки. Никаких команд записи на SD эта сборка не выполняет.

В терминологии статьи нужно различать *read-only discovery of FAT32 layout* и *read-only FAT32 file access*: второй функционал требует разбор FAT-цепочек и каталогов и здесь ещё отсутствует.

## Аппаратный результат SD-03.4 — 24 октября 2026

После разбиения расчётов BPB на последовательные такты временной анализ Gowin для исправленного проекта на 27 МГц дал **0 нарушений setup, 0 нарушений hold, TNS = 0.000 нс**. Использование: **2764/8640** логических ресурсов, **1949/6480** FF и **4% BSRAM**. Контрольная сумма проверенного оператором `.fs`: `2F5221EA95F91EE27F4B5BD2E10B4738CAF592F2113EC807A0C68433EFBF51A2`.

Непосредственно с физической платы Tang Nano 9K оператор получил:

```text
SD03 RESULT=MBR_FAT32    VOL=00000040 FAT=00000840 DATA=00004440 ROOT=00004440 CLUS=000EFFDF E=00
```

Расшифровка абсолютных адресов: раздел начинается с **LBA 64**, первая FAT — **LBA 2112**, область данных и начальный кластер корневого каталога — **LBA 17472**, вычисленное количество кластеров — **983007**. Разность `FAT−VOL` равна **2048** зарезервированных секторов, а `DATA−FAT` — **15360** секторов совокупной области FAT. Значение `E=00` означает отсутствие зарегистрированной ошибки чтения в контроллере.

Это **аппаратный функциональный PASS для обнаружения структуры тома FAT32**, а не для чтения файлов. Реальное чтение каталогов, FAT-цепочек и полное сравнение образа карты с независимым ПК пока не выполнялись. Задержка возврата MISO от внешнего устройства не прошла полный timing sign-off.
