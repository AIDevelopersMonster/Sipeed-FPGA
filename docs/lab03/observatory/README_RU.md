# LAB-03 · PicoRV32 Bus Trace Observatory (актуальный стенд v1.1.0)

**Назначение:** наглядно исследовать события процессорной шины *на физической* Tang Nano 9K (GW1NR-9C), а не только смотреть на итоговую строку `PASS`. Стенд воспроизводит **сохранённые аппаратные наблюдения** и по запросу подключается к плате через Web Serial. Не создает вымышленную временную диаграмму и не выдаёт выборку (FETCH) за завершённую инструкцию (retirement).

## Важнейшие свойства

- В комплекте находятся **оригинальный неизменённый архив LAB03_3_EVIDENCE.zip и 12 настоящих T3-захватов** из `LAB03_3_EVIDENCE.zip`: 6 команд `0`, 6 команд `4`, всего **269 FETCH** и 12 финальных `LED_WRITE`.
- Стенд проверяет **SHA-256 каждого сырого дампа**, строгую структуру T3, статус флагов, 256 слов *правильного* `lab03_boot.hex` и соответствие наблюдаемых инструкций ROM.
- На экране: динамическая диаграмма 12 измерений, интерактивная шкала событий, инспектор адреса/слова/цикла, базовый дизассемблер RV32I, логическая маска светодиодов, журнал событий, просмотр от первого FETCH до LED_WRITE.
- Сопоставление: два аппаратных захвата или аппаратный захват и **самостоятельно загруженный** T3-файл из Icarus. Совпадение проверяется по `(kind, address, value)` от единственного FETCH `PC=0x048` до финального `LED_WRITE`, после проверки структуры префикса UART polling.
- Встроены краткие контекстные подсказки и справочник стандартных терминов, практические задания и экспорт заполненного протокола в Markdown.
- Никаких CDN, облака, регистрации или сторонних JS-зависимостей. Приложение в браузере не перепрограммирует FPGA и не меняет драйверы.

## Практическое занятие

1. Открыть **Наблюдение**. Выбрать аппаратный запуск №1 (команда `4`), нажать воспроизведение, остановиться на событиях `FETCH`, затем на финальной записи `LED_WRITE`.
2. Рассмотреть **PC (адрес)**, **машинное слово** и **RV32I mnemonic**. Навести курсор/установить фокус на значок `?` для пояснения термина. Найти значение MMIO по адресу `0x20000000`.
3. На диаграмме выбрать разные захваты одной команды; выписать количество FETCH и выяснить, какая часть трассы меняется. Вкладка **Сопоставление** показывает полный префикс и нормализованный участок.
4. Выбрать два аппаратных запуска одной команды и сравнить их нормализованные сигнатуры; затем выбрать разные команды и объяснить несовпадение.
5. **Опционально:** после запуска RTL-теста `01-PicoRV32/tools/run_lab03_4_rtl_v03.ps1` импортировать в разделе **Сопоставление** файлы `01-PicoRV32/build/lab03_4_trace_0.txt` и `01-PicoRV32/build/lab03_2_trace_4.txt`. Можно импортировать одноимённые копии из `build/lab03_4/rtl_compare_v03/run_.../`. Результат не подтверждает аттестацию происхождения загруженного файла.
6. Вкладка **Протокол студента** → указать гипотезу, измерения, интерпретацию, границы доказательства → сохранить `.md`.

## Подключение реальной платы

**Нужны:** плата с уже загруженной в FPGA SRAM правильной LAB-03.2 конфигурацией, работающий USB-UART, Chromium или Microsoft Edge с Web Serial, адрес **http://127.0.0.1:8765/** (без `https://` и без открытия файла `file://`).

- **Не меняйте USB-драйверы** и не используйте openFPGALoader для этого шага. В нашем стенде плата ранее была запрограммирована штатным Gowin Programmer CLI через FT2CH. Важно использовать именно прошивку LAB-03.2 с ответом `T3`, а не LAB-02.
- Закройте Chrome/Edge-вкладки с Web Serial, PowerShell-терминалы, другие приложения, удерживающие COM10. Только одно приложение может открыть последовательный порт.
- Нажать **Подключить COM-порт**, выбрать подключённый USB-UART. Интерфейс не предполагает, что порт всегда называется COM10 — выбор делает пользователь.
- Выбрать команду `0…6`, нажать **Захватить**. Приложение последовательно отправит три одиночных ASCII-команды: `C`, `0…6`, `T`, дождётся `C`, `L=n`, а затем получит `T3:…`, `E:…`, `Z`. Выполняется строгий разбор событий и контроль ROM.
- **T · Повторить чтение** повторно запрашивает уже сохранённый снимок без `C`. Кнопка **? · Состояние** читает LED-регистр; ни одна из них не создаёт новый аппаратный захват.
- Подключение порта производится только по инициативе пользователя. Браузерный код не записывает .fs, не запускает Gowin и не пишет во Flash.

## Ограничения измерения и языка выводов

1. FETCH означает только **принятое обращение к ROM**. Наш регистратор не видит архитектурного завершения (retirement); возможен look-ahead на переходах.
2. Префикс опроса UART (`PC=0x038/03C/040/044`) различается по длине. Для сравнения исключается **только проверенный** префикс перед единственным FETCH `PC=0x048`.
3. «Светодиод включён» в анимации означает **логическое значение `LED_WRITE`**. Оно не заменяет наблюдение физической платы глазами или датчиком. Выводы платы active-low.
4. Относительные значения циклов отображаются как данные захвата, но **не сравниваются** между FPGA и RTL и не используются как такты завершения инструкций.
5. Сопоставление с RTL требует **реального файла RTL-T3, загруженного пользователем**; по умолчанию комплект включает только аппаратные трассы. Никаких подставных «RTL» образцов.
6. SHA-256 `picorv32_lab03_nano9k.fs` `62596847…f13` указан из кампании; **чтение активной SRAM FPGA не проводилось**. Без отдельной проверки не следует заявлять битовую эквивалентность конфигурации.
7. Нет авторизации, облачной синхронизации, сохранения введённого отчёта внутри приложения: экспортируйте Markdown перед закрытием страницы.

## v1.1.0 — методический комплект и разбор реальных инструкций RV32I

**Новая вкладка «03 Команды RV32I»** строит каталог строго из проверенных T3-записей
либо из указанного ROM. В архивных 12 трассах наблюдаются **6 мнемоник**
(`addi`, `andi`, `beq`, `jal`, `lw`, `sw`); активная программа ROM содержит
**10** (`+ lui`, `bne`, `srli`, `jalr`), а **54 хвостовых NOP** показываются
отдельно. Карточки содержат реальные адреса PC, машинные слова, бинарное
представление, opcode, синтаксис, семантику и контекст работы именно нашей
прошивки, со ссылкой «↗ В трассу» на измеренное событие. Из инспектора событий
есть кнопка «↗ Объяснить эту команду».

Сохраняется различие **выборки FETCH**, **принятой записи LED_WRITE** и
**архитектурного завершения** инструкции (не наблюдается).
