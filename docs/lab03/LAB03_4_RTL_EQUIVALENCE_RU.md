# LAB-03.4 v0.2 — сопоставление аппаратной и RTL-трасс PicoRV32

**Состояние перед запуском:** аппаратный ROM match 269/269 (12 захватов), отдельная симуляция и эквивалентность ещё не выполнены.

## Задача

Сопоставить подтверждённые шиной события `FETCH` и `LED_WRITE` для команды `4` на физической Tang Nano 9K и в Icarus Verilog. Не выдавать простое совпадение количества FETCH за эквивалентность. В этом этапе `FETCH` — принятое чтение слова инструкции; завершение инструкции (retirement) не наблюдается.

## Почему существующий testbench достаточен для первого сравнения

`tests/tb_lab03_2_uart.v` создаёт `build/lab03_2_trace_4.txt`, `build/lab03_2_trace_4_repeat.txt`, `build/lab03_2_trace_1.txt`. Тест проверяет UART 8N1, UART-команду `4`, чтение `T`, повторное неизменяемое `T`, очистку `C`, следующую команду `1` и фиксирует `LAB03_2_UART_TRACE_RTL_PASS`. Аппаратная серия содержит 6 запусков `4` и 6 запусков `0`. На этапе v0.2 сравнивается **только команда 4**; команда 0 потребует расширения тестбенча.

## Правило сравнения

1. Все аппаратные файлы и SHA-256 сверяются с журналом серии; все 269 аппаратных FETCH — с отдельной прошивкой `firmware/lab03_boot.hex`.
2. RTL-трасса читается из действительного UART-вывода testbench. В журнале требуется маркер `LAB03_2_UART_TRACE_RTL_PASS`.
3. Все RTL FETCH проверяются по тому же ROM. Потребуются принятые записи на шине, а не догадки о процессорном PC.
4. Переменный начальный префикс опроса UART в последовательности `0x038,0x03C,0x040,0x044` отсекается по единственному наблюдаемому FETCH с PC `0x048`.
5. События от этого PC до конечного `LED_WRITE` сравниваются **полностью** по `(kind, addr, word/value)`, включая опережающие выборки. Числа циклов и индексы событий не сравниваются.
6. При первом расхождении выводится пара событий и сохраняется файл `core_comparison.csv` с полным сравнением.

Дополнительно проверяет декодирование RTL T3 существующим `lab03_trace_decode.py`.

## Строгая граница утверждения

Успех означает **эквивалентность наблюдаемых сигнатур принятых шиной событий для одной команды** в определённом стабильном окне, при данном ROM и источниках RTL. Это не потактовая эквивалентность; не подтверждение retirement; не доказательство эквивалентности для всех команд или состояний; не доказательство однозначной идентичности содержимого текущей SRAM со всей сборкой. Ключевое ограничение: рабочее дерево проекта на момент аппаратной серии было dirty; `git rev-parse HEAD` один не удостоверяет всю версию RTL.

**Промежуточная аттестация:** если сравнение завершится кодом 0, можно фиксировать `RTL_BUS_TRACE_CORE_EQUIVALENCE_PASS` только для команды `4`. До фактического исполнения не присваивать PASS.

## Тесты

Восемь тестов проверяют сравнение на синтетическом/переиспользованном аппаратном потоке как на *имитации RTL*. Это проверка анализатора, **не самостоятельное выполнение RTL**. Для действительного RTL-результата обязателен запуск Icarus Verilog на целевой рабочей копии.

Перед перезаписью жёстко именованных `build/lab03_2_trace_*.txt` скрипт копирует прежние результаты в каталог `build/lab03_4/previous_rtl_*`. Новые RTL-снимки, лог компиляции и лог моделирования дополнительно сохраняются в `build/lab03_4/rtl_compare_4/` вместе с SHA-256 использованных исходных файлов и состоянием Git.
