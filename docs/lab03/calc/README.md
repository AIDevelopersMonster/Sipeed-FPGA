# PicoRV32 · LAB-03 — Calc Observatory / RV32I bit decoder

**v1.1 · LibreOffice Calc (`.ods`) и Excel (`.xlsx`) · без макросов**

Это самостоятельная учебная модель PicoRV32 на Tang Nano 9K (SoC LAB-03). Она использует **сохранённые аппаратные T3-трассы** и точно определённый образ ROM LAB-03. Никакого нового UART-захвата и программирования FPGA сама таблица не выполняет.

### Что происходит внутри основной книги

- **«ПУЛЬТ»** — выбор одного из 12 *сохранённых аппаратных захватов* и конкретного события; это просмотр измеренного, а не новый замер.
- **«РАЗБОР RV32I»** — значения битов `opcode`, `rs1`, `rs2`, `rd`, `funct3` и `imm` для выбранного машинного слова (в зависимости от формата).
- **«10 КАРТОЧЕК»** — готовые образцы декодирования десяти мнемоник нашей ROM.
- **«КАТАЛОГ БИТОВ»** — побитовый справочник 202 рабочих слов программы по адресам PC.
- **«МОДЕЛЬ MMIO»** — вычисляемый эксперимент: ввод `4`, `5`, `6` даёт маски `0x08`, `0x10`, `0x20`; **не** следует выдавать расчёт для `5`/`6` за один из 12 сохранённых T3-захватов (в них представлены команды `0` и `4`).

**Важно о доказательствах:** `FETCH` — подтверждённое шинное чтение слова инструкции, а **не** retirement; `LED_WRITE` — подтверждённая запись в MMIO, а **не** измеренная яркость светодиода. Декодер интерпретирует ROM, но не моделирует потактовое исполнение PicoRV32.

## Быстрый запуск

1. Откройте [книгу LibreOffice Calc](LAB03_PicoRV32_Excel_Observatory_v1.1_RV32I.ods) в LibreOffice Calc. Для Microsoft Excel есть [версия XLSX](LAB03_PicoRV32_Excel_Observatory_v1.1_RV32I.xlsx).
2. На листе **«ПУЛЬТ»**: `D6=5`, `I6=27` — событие `FETCH`, `PC=0x00000100`, машинное слово `0x01D2A023`, инструкция `sw t4, 0(t0)`.
3. Измените `I6` на `28` — `FETCH` инструкции `lw t6, 0(t0)`; затем на `29` — отдельное `LED_WRITE` с адресом `0x20000000` и значением `0x00000008`. **LED_WRITE не является инструкцией.**
4. Откройте **«РАЗБОР RV32I»**, оставьте `H6=ТРАССА`: поля S/I/B/J/U-type декодируются по выбранному событию. Для просмотра всей программы переключите `H6=РОМ` и изменяйте индекс `D6` (1–202).
5. На листе **«МОДЕЛЬ MMIO»** изменяйте команду в `D8`: `4 → 0x08`, `5 → 0x10`, `6 → 0x20`. Код инструкции `sw` остаётся `0x01D2A023`. Это **вычисляемая модель**, а не новое аппаратное измерение.
6. Просмотрите **«10 КАРТОЧЕК»** и **«КАТАЛОГ БИТОВ»**. При необходимости пересчитайте формулы через `Ctrl+Shift+F9`.

## Что подтверждено и что не подтверждено

- 12 сохранённых аппаратных трасс: **269 FETCH**, **12 LED_WRITE**, **29 разных PC**; для архивной кампании команды `0` и `4` встречаются по шесть раз.
- Проверены 202 рабочих машинных слова ROM (плюс 54 слова `nop` как заполнение). Из десяти мнемоник ROM шесть встречаются в зарегистрированных FETCH.
- `FETCH` подтверждает **принятую шинную выборку слова**, но не завершение инструкции (retirement); графические LED в книге — визуализация данных, не оптическое измерение.
- В книге есть 14 листов; служебный лист расшифровки полей может быть скрыт.

Для **проверки опубликованного комплекта**, не изменяя файлы, достаточно стандартной библиотеки Python:

```powershell
cd C:\GitHub\Sipeed-FPGA\docs\lab03\calc
python .\verify_calc_bundle.py
```

Для **необязательной пересборки** XLSX нужен `openpyxl`. Пример сохраняет результат во временный каталог, чтобы не перезаписывать опубликованную книгу и не нарушать SHA-256 исходного комплекта:

```powershell
python -m pip install openpyxl
python .\build_rv32i_bits.py --out "$env:TEMP\LAB03_RV32I_rebuilt.xlsx"
```

После осознанного изменения или замены файлов контрольные суммы необходимо пересчитать. Сборщик формирует **XLSX**; нативная `.ods` получена отдельным импортом/сохранением в LibreOffice Calc. Не считайте её результатом работы Python-сборщика.
