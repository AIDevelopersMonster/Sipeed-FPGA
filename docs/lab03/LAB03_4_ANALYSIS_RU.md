# LAB-03.4 v0.1 — независимый аудит трасс PicoRV32 (Tang Nano 9K)

**Статус выпуска:** реализован офлайн-анализатор и 8 синтетических тестов. На предоставленном аппаратном архиве `LAB03_3_EVIDENCE.zip` проверены 12 дампов (см. отдельный результат `LAB03_4_AUDIT_20261021.zip`). Это **не** доказательство RTL-эквивалентности или retirement.

## Задача

Получить проверяемое описание аппаратных UART-трасс LAB-03.2/03.3 без повторного программирования FPGA. Независимо проверить хеши файлов, состав событий, PC и слова инструкций, локализовать вариативность трасс и отдельно сравнить их с эталонным ROM.

## Установка (Windows PowerShell 7)

Распакуйте `LAB03_4_analysis_v0.1.zip` в корень существующего репозитория `C:\GitHub\Sipeed-FPGA`. Архив добавляет три новых файла и ничего не перезаписывает в существующем проекте.

```powershell
cd C:\GitHub\Sipeed-FPGA
Expand-Archive "$HOME\Downloads\LAB03_4_analysis_v0.1.zip" -DestinationPath . -Force
python .\01-PicoRV32\tests\test_lab03_4_analyze.py
python .\01-PicoRV32\tools\lab03_4_analyze.py `
  --evidence "$HOME\Downloads\LAB03_3_EVIDENCE.zip" `
  --out .\01-PicoRV32\build\lab03_4\audit_20261021
```

Здесь используется только стандартная библиотека Python 3.10+; доступа к COM10, JTAG, Gowin и интернету нет. Не перепрограммирует FPGA.

Результаты: `report.md`, `summary.json`, `decoded_events.csv`, `observed_words.csv` в каталоге `--out`.

## Что в действительности проверяется

- SHA-256 каждого из 12 исходных файлов `raw/*.txt` относительно архивного `runs.csv`.
- Согласованность `runs.csv`, `runs.json`, `manifest.json` и хеша используемого PowerShell-probe.
- Грамматика `T3/E/Z`, номера событий, относительные циклы (монотонность), состав FETCH и один завершающий LED_WRITE.
- Объявленная команда, MMIO-адрес `0x20000000`, значение LED и данные ROM (по указанному источнику).
- Отсутствие противоречащих слов для одинакового PC между разными трассами.
- Для **данного образца LAB-03.2**: циклический префикс FETCH `0x038,0x03C,0x040,0x044` и общая последовательность событий от `0x048` до LED_WRITE для одинаковых команд.

**Важно:** события FETCH — принятые чтения слов инструкций с шины. Это не поток *retirement/commit*. Переход по PC нельзя интерпретировать как строгий переход исполняемого управляющего графа без учёта prefetch/look-ahead.

## Обнаруженное в реально предоставленном архиве

- 12/12 исходных хешов верны, 269 FETCH, 29 разных PC, 0 конфликтов по словам.
- Команда 0: 14 одинаковых FETCH после `0x048`, +3–6 начальных FETCH опроса UART.
- Команда 4: 22 одинаковых FETCH после `0x048`, +2–6 начальных FETCH опроса UART.
- Приложенный `boot.hex`: 216 несовпадений из 269 FETCH, 25 уникальных несовпадающих PC. Это указывает на несовместимость **приложенного эталона** с наблюдаемыми событиями, а не обязательно на неисправность FPGA.

## Как продолжать

Для проверки ROM получите `boot.hex`, который **доказуемо** соответствует бинарному образу `.fs`, запрограммированному для этих измерений. Источник в репозитории может быть неэквивалентен, поскольку манифест указывает `working_tree_dirty=true`. Дополнительный ROM можно указать явно:

```powershell
python .\01-PicoRV32\tools\lab03_4_analyze.py `
  --evidence "$HOME\Downloads\LAB03_3_EVIDENCE.zip" `
  --rom 'C:\path\to\exact-build\boot.hex' `
  --out .\01-PicoRV32\build\lab03_4\exact_rom_audit
```

И даже полное совпадение слов ROM означает только **ROM_WORDS_MATCH** по наблюдаемым адресам. Для `RTL_BUS_TRACE_EQUIVALENCE_PASS` потребуется отдельный RTL-дамп при идентичных ROM, сценарии, границах захвата и логике регистрации.

Репозиторий: `AIDevelopersMonster/Sipeed-FPGA`, ветку и изменения проверяйте через `git status -sb` перед коммитом. Сырые данные и отчёты находятся в игнорируемом `build/`; не следует случайно коммитить аппаратные дампы и битстримы.
