# LAB-03.2 — аппаратная трасса PicoRV32 через UART

**Проект:** Sipeed-FPGA · **Плата:** Tang Nano 9K, GW1NR-9C · **Этап:** v0.1.0, 20.10.2026

**Верификационный статус на момент подготовки:** Python-предпроверка протокола и программной модели — PASS. RTL (Icarus), Gowin PnR/STA и реальная FPGA — **PENDING**. Наличие исходников и результата программной модели не доказывает аппаратную работоспособность.

## 1. Инженерная цель

LAB-03.1 реализовала в Icarus пассивное сохранение событий реальной шины PicoRV32: подтверждённые чтения инструкций и записи в LED MMIO. LAB-03.2 добавляет полноценный синтезируемый top-level SoC, регистры чтения снимка, самостоятельную RV32I-прошивку и передатчик трассы **через штатный UART**, используя существующий процессор и TX-периферию.

**Не меняем LAB-02:** файл `rtl/picorv32_soc.v`, исходный `firmware/boot.S`, генерируемые `boot.hex`, `boot_rom.v` и обычный `gowin_build.tcl`. Новый top — `picorv32_soc_lab03`, ROM — `lab03_boot_rom`, битовый поток — `picorv32_lab03_nano9k.fs`.

## 2. Проверяемые свойства

| Свойство | Механизм | Граница |
|---|---|---|
| Регистрация FETCH | `mem_valid && mem_ready && mem_instr && !mem_wstrb` | Только принятая выборка, не retirement |
| Регистрация LED_WRITE | Подтверждённая запись по `0x20000000` | Регистр, не измерение света |
| Буфер событий | 128 × 82 бит + признаки `done/truncated/overlap/wrapped` | Потеря полноты явно отмечается |
| Неподвижный снимок | `T` читает; `C` явно сбрасывает и перевооружает | Новая команда LED без `C` не перезаписывает старый снимок |
| Последовательный протокол | ASCII `T3`, `E`, `Z`, строго 8 hex-символов на поле | В v0.1 нет CRC |
| Уровень RTL | Настоящий PicoRV32 + самостоятельная ROM + UART TX/RX | Только после успешных Icarus-тестов |

Адреса MMIO (все относятся к базовому адресу `0x20000000`):

| Смещение | Назначение |
|---|---|
| `+0x00` | LED R/W, существующая LAB-02 |
| `+0x10/14/18/1C` | UART TX, TX-статус, RX, RX-статус — как в LAB-02 |
| `+0x20` | TRACE_STATUS: `[31:24]=03`, `[23:16]=80`, `[12]=capturing`, `[11]=wrapped`, `[10]=overlap`, `[9]=truncated`, `[8]=done`, `[7:0]=count` |
| `+0x24` | TRACE_COMMAND — ASCII-команда-триггер |
| `+0x28` | TRACE_INDEX — запись индекса запускает синхронное чтение RAM |
| `+0x2C` | TRACE_META = `{14'b0, kind[1:0], cycle[15:0]}` |
| `+0x30` | TRACE_ADDR |
| `+0x34` | TRACE_VALUE (ROM-слово или записанные данные LED) |
| `+0x38` | TRACE_CLEAR — запись сбрасывает снимок и перевооружает |

**Протокол UART** — посылать отдельные байты без CR/LF:

- `0`–`6`: выбрать LED / все OFF, подтверждение `L=n\n`.
- `?`: получить текущее состояние LED, подтверждение `L=n\n`.
- `C`: сбросить накопленную трассу, ответ `C\n`.
- `T`: передать снимок:

```text
T3:03800116:00000034
E:00000000:00010000:00000000:XXXXXXXX
E:00000001:00010004:00000004:YYYYYYYY
...
E:00000015:00020080:20000000:00000008
Z
```

**ВНИМАНИЕ:** блок выше — **пояснительный пример формата**, не реальная запись лаборатории; номера, временные метки и слова `XXXXXXXX`, `YYYYYYYY` не являются измерением. Реальные данные декодер получает непосредственно из UART и сравнивает с `lab03_boot.hex`. Длина каждого поля — ровно 8 шестнадцатеричных цифр, когда это настоящая передача.

`T3` означает версию кадра. Первое слово — `STATUS` (глубина, полнота, количество), второе — ASCII-триггер, записанный как 32-битное число. Строки `E` содержат индекс, упакованные тип и 16-битный относительный цикл, адрес и значение. Последняя строка — `Z`. CRC в v0.1 не предусмотрен: утверждать абсолютную целостность передачи нельзя.

## 3. Повторение на Windows PowerShell 7

**Пункт 1 — установка:** использовать архив LAB-03.2 и его `Install-LAB03_2.ps1`. Установщик принимает ветку `feature/picorv32-lab03-trace-recorder` на коммите `c977184`, создаёт новую ветку `feature/picorv32-lab03-uart-trace`, копирует только новые файлы и расширяет SHA256-манифест. Семь прежних неотслеживаемых файлов и исходники LAB-02 он не меняет.

**Пункт 2 — модель и протокол:**

```powershell
Set-Location C:\GitHub\Sipeed-FPGA
& .\01-PicoRV32\tools\test_lab03_2.ps1 -ModelOnly
```

Ожидается `LAB03_2_ASSEMBLE_PASS`, `LAB03_2_PROTOCOL_PARSER_PASS`, `LAB03_2_FIRMWARE_MODEL_PASS`, `LAB03_2_MODEL_PASS`. Модель не подтверждает RTL-тайминги.

**Пункт 3 — полный RTL:** потребуется Python, `iverilog`, `vvp`, зафиксированное ядро PicoRV32:

```powershell
& .\01-PicoRV32\tools\fetch_picorv32.ps1
& .\01-PicoRV32\tools\test_lab03_2.ps1
```

Ожидается `LAB03_2_UART_TRACE_RTL_PASS`, три успешных вывода `LAB03_2_TRACE_DECODE_PASS` и `LAB03_2_RTL_PASS`. Тест моделирует настоящий UART 115200 8N1, проверяет команду `4`, `T` дважды, `C`, `1`, `T`, не меняет старую ROM LAB-02.

**Пункт 4 — аппаратный этап ТОЛЬКО после RTL_PASS:**

```powershell
& .\01-PicoRV32\tools\build_lab03_2.ps1
```

Изучите использование LUT/FF/BRAM, отчёт PnR и STA. **Нельзя считать Gowin PASS по одному коду возврата**. После успешных отчётов и подтверждения правильного файла программировать только **SRAM** новым `picorv32_lab03_nano9k.fs`; **нажать и отпустить S2 после программирования**.

**Пункт 5 — чтение реальной трассы (после аппаратной проверки и загрузки LAB-03.2):** закройте HTML Web Serial и другие программы, занимающие COM. Пример для стенда с COM10:

```powershell
& .\01-PicoRV32\tools\probe_lab03_2_serial.ps1 -PortName COM10 -CaptureNew -Led 4
```

Скрипт пошлёт `C`, получит `C`, пошлёт `4`, получит `L=4`, пошлёт `T`, сохранит поток в `01-PicoRV32/build/` и проверит машинные слова по настоящему `lab03_boot.hex`. COM закрывается в `finally` при любой ошибке. После этого вручную проверьте свечение L4. **Пока данный аппаратный тест не выполнен, BOARD_PASS не объявляется.**

## 4. Критерий приёмки

Получить на физической плате замороженный снимок с корректной версией, индексами 0..N−1, подтверждёнными FETCH по настоящей ROM и завершающей записью `0x8` в `0x20000000`; увидеть реальный L4. После повторного `T` снимок должен быть идентичен. После `C` и команды `1` должен появиться новый снимок с завершающей записью `0x1`. И только затем ставить `BOARD_PASS`.
