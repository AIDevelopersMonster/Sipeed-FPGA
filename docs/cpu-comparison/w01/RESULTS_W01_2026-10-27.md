# LAB-06 W01 — Final physical FPGA benchmark / Итоговый протокол

**Date: 2026-10-27. Status: W01 HARDWARE UART / CYCLE PASS, BOTH CPUs. Experimental campaign complete with explicit limitations.**

Source of measured figures: user-supplied Gowin Programmer and Python serial-console transcripts. Local ignored `_build` receipts are identified below; this published report does not claim to have independently retrieved them.

## Conditions and what is actually being compared

- Device: Sipeed Tang Nano 9K, Gowin GW1NR-9C, **27 MHz** input clock, no PLL/DSP.
- Cores: PicoRV32 (pinned upstream `ef203c2b0a3fb793280f5114941416c425c5b461`) and NEORV32 (pinned `b2620454ebb2407e81a6a1965ef52e2a860b0432`).
- Both: RV32I execution, Zicntr `cycle` counters enabled for W01; 16 KiB on-chip ROM, 2 KiB on-chip RAM, UART 115200 8N1, GPIO6, volatile SRAM configuration.
- Exactly the same **62 RV32I machine instruction words** in the common `w01_workload` function, confirmed by compiler-gate disassembly. The surrounding platform firmware/bus/UART implementation differs between SoCs and is not claimed to be byte-identical.
- Workload: 32 RAM words, 256 ALU/shift/branch/load/store updates, deterministic reference digest `B26F8CA7`.
- `cycle` CSR measured before and after the workload call. UART emission and GPIO status changes are **outside** the measured interval; the measurement includes the call/return and actual memory-system service.

## Limitations and disposition

1. **LED status for these specific W01 images remains PENDING.** The physical UART/cycle result is independently accepted; the W01 console explicitly requests an LED visual check, and the user has not provided that observation in this test. Earlier basic LAB-06.1/06.2 UART/LED tests did confirm three lights, but that is different firmware.
2. **Pico async reset deassertion is NOT timing-qualified.** Recovery/Removal say `Nothing to report!`, meaning no analyzed paths, not a measured positive slack. The simple clock-only SDC does not fully characterize external asynchronous reset and UART input timing. NEORV32 Recovery/Removal are positive in its existing PnR summary.
3. **BSRAM 54% vs 20% has no demonstrated causal attribution.** Both SoCs nominally use 16 KiB ROM + 2 KiB RAM, but physical inference, register files, native bus and peripherals differ. Summary percentages are insufficient to identify which specific primitive creates the disparity. **Do not claim the bare PicoRV32 CPU needs 54% BSRAM.**
4. W01 is a single deterministic 256-round **CPU + native memory system** workload. It is not core-only ALU latency, a full ISA compliance suite, physical Fmax characterization or a repeated statistical benchmark.
5. Gowin `operation_index 2` wrote only **volatile SRAM**. No configuration Flash, SD writes or changes to previously accepted bitstreams.
6. W02/W03 and additional CPU board trials are **CANCELLED** per the agreed scope and stopping criteria. No new runs are necessary to close the numerical comparison.
