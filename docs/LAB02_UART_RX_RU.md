## 1. Цель, учебные результаты и маршруты

**Цель:** расширить ранее проверенную минимальную RISC-V SoC приёмником UART, выполнить управление физическими выходами FPGA через PicoRV32 и связать педагогическую модель исполнения инструкции `SW` с подтверждённым физическим эффектом.

По окончании работы студент должен уметь:

1. Различать процессор PicoRV32, программу RV32I в ROM, периферийные регистры MMIO и выводы FPGA.
2. Объяснять передачу команд по UART RX и обратное подтверждение по UART TX, отличие ответа `L=n` от электрического или оптического измерения.
3. Воспроизвести модель, RTL-тесты, Gowin PnR/STA и программирование **только конфигурационной SRAM**.
4. Проверить включение каждого выбранного LED, включая смену состояния при движении **13 → 14 → 13 → 14** в HTML.
5. Различать синхронизацию *события и подтверждения* и непосредственную тактовую трассировку реального процессора.

**Маршрут A — демонстрационный:** преподаватель предоставляет уже проверенную конфигурацию `.fs` вместе с SHA256; студент загружает её в SRAM, проверяет UART и работает с HTML. Готовый испытуемый `.fs` не следует предполагать в публичном Git-репозитории: файл сборки может быть исключён из Git.

**Маршрут B — инженерный (выполненный в данном протоколе):** студент самостоятельно запускает модель и RTL-тесты, собирает проект в Gowin, исследует STA, программирует SRAM, выполняет COM- и HTML-тесты. Все этапы выполняются на одной и той же экспериментальной версии LAB-02.

**Электрические назначения в проверенном файле ограничений:** UART TX — FPGA pin 17, UART RX — pin 18; LED L1–L6 — pins **10, 11, 13, 14, 15, 16**. LED активны *низким* уровнем: логическая `1` в регистре `leds` означает `0` на соответствующем `led_n[i]` и включённый светодиод. Дополнительные провода для лабораторной не требуются.

Сборка или успешный UART-тест не доказывают, что произвольная будущая версия SoC прошла проверку: любое изменение RTL/ROM требует соответствующего повторения тестов.

## 3. Архитектура и проверяемые свойства

```text
Windows PC / Chrome-Edge / PowerShell
               | USB, COM10 (в данном эксперименте)
      встроенный USB-UART платы
               | RX pin 18 / TX pin 17
 +-------------v--------------------------+
 | GW1NR-9C, 27 MHz                       |
 | UART_RX -> FIFO(4) -> MMIO -> PicoRV32 |
 |                  ^          |          |
 |                  +--- ROM <-+          |
 |                       |                 |
 | PicoRV32 -> MMIO LED -> led_n[5:0]     |
 | PicoRV32 -> UART_TX -> USB-ответ       |
 +-----------------------+----------------+
                         |
                   L1 ... L6
```

Процессор исполняет **118 машинных инструкций RV32I** из 1-КиБ ROM (оставшиеся слова ROM заполняются NOP). Здесь нет RAM, стека, C runtime, прерываний или операционной системы. UART RX имеет двухкаскадный синхронизатор, выборку в середине бита и FIFO на четыре байта; предусмотрены признаки переполнения и ошибки стопового бита. Этот минимальный приёмник **не** является многократным передискретизатором с голосованием большинства. Запросы следует отправлять по одному с ожиданием ответа.

### 3.1. Карта памяти MMIO

| Адрес | Регистр | Доступ / смысл |
|---|---|---|
| `0x20000000` | LED | R/W, младшие 6 бит |
| `0x20000004` | CYCLES | R/O, свободно работающий счётчик |
| `0x20000008` | DEVICE_ID | R/O, `0x5A5A0001` (программная сигнатура, не JTAG ID) |
| `0x2000000C` | TEST_STATUS | R/W, сохранён из исходной SoC |
| `0x20000010` | UART_TX | запись младшего байта |
| `0x20000014` | UART_STATUS | бит 0 — TX готов |
| `0x20000018` | UART_RX_DATA | чтение извлекает байт из FIFO |
| `0x2000001C` | UART_RX_STATUS | бит 0 — данные есть; бит 1 — overrun; бит 2 — framing error; запись очищает флаги ошибок |

### 3.2. Протокол и таблица светодиодов

| Символ с ПК | Маска LED | Активный физический вывод | Ответ PicoRV32 |
|---|---|---|---|
| `0` | `0x00` | все HIGH, LED выключены | `L=0` |
| `1` | `0x01` | pin 10 → LOW, L1 | `L=1` |
| `2` | `0x02` | pin 11 → LOW, L2 | `L=2` |
| `3` | `0x04` | pin 13 → LOW, L3 | `L=3` |
| `4` | `0x08` | pin 14 → LOW, L4 | `L=4` |
| `5` | `0x10` | pin 15 → LOW, L5 | `L=5` |
| `6` | `0x20` | pin 16 → LOW, L6 | `L=6` |
| `?` | не изменяет | чтение текущего MMIO-состояния | `L=n` |

После сброса прошивка обнуляет LED и отправляет `READY\n`. Команда `0`–`6` вызывает **реальную запись `SW` в регистр LED**, затем чтение `LW` этого же регистра. При совпадении возвращается `L=n\n`, при несовпадении — `F\n`; неизвестные символы дают `E\n` (CR/LF игнорируются). **`n` — номер выбранного LED, а не двоичная маска.** Возврат `L=n` подтверждает *прочитанное значение MMIO*, но не заменяет визуальную проверку свечения.

### Шаг B5. Двусторонняя проверка UART и физический LED

```powershell
Set-Location C:\GitHub\Sipeed-FPGA
& .\01-PicoRV32\tools\probe_lab02_serial.ps1 -PortName COM10
```

Скрипт быстро отправляет `0, 1, 4, ?, 6, 0` и проверяет ответы. При успехе выводит `LAB02_SERIAL_ACK_PASS`. **Не рассчитывайте успеть рассмотреть светодиоды:** этот тест автоматический. Для зрительного подтверждения передавайте команды по одной с паузой до Enter (пример ниже). COM-порт допускает только одного владельца; закройте PowerShell-тест перед Web Serial.

```powershell
$sp = [System.IO.Ports.SerialPort]::new('COM10',115200,
  [System.IO.Ports.Parity]::None,8,[System.IO.Ports.StopBits]::One)
$sp.NewLine = "`n"
$sp.ReadTimeout = 2000
try {
  $sp.Open()
  Start-Sleep -Milliseconds 500
  $sp.DiscardInBuffer()
  foreach ($t in @(@('1','L1'),@('4','L4'),@('6','L6'),@('0','ALL OFF'))) {
    $sp.Write($t[0])
    $reply = $sp.ReadLine().Trim()
    Write-Host "$($t[0]) -> $reply; observe $($t[1])"
    Read-Host 'Нажмите Enter после осмотра платы' | Out-Null
  }
} finally { if($sp.IsOpen){$sp.Close()}; $sp.Dispose() }
```

Проверка глазами важна: она связывает ответ регистра с физическим результатом на плате. При ошибке первым делом проверить порт, конфигурацию LAB-02 в SRAM и отсутствие другого владельца COM; не начинать с переписывания Verilog или переустановки драйверов.

### Задание H1. Выбор светодиода и первые 13 шагов

1. Нажмите **«Подключить COM»**, разрешите доступ к штатному UART платы.
2. Выберите любой LED, например **L4** (маска `0x08`, FPGA pin 14).
3. Перейдите с начального состояния по **шагам 1–13**, наблюдая ROM, регистры `x5`, `x6` и поля `mem_addr`, `mem_wdata`, `mem_wstrb`, `mem_valid`, `mem_ready`.
4. До подтверждения записи в модельном шаге 14 выбранный светодиод должен оставаться выключенным.

### Задание H2. Шаг 14 и обратимое учебное действие

1. **13 → 14.** HTML отправляет `'4'`; реальный PicoRV32 выполняет MMIO-запись и чтение, возвращает `L=4`; L4 на плате загорается, а HTML показывает подтверждённое состояние.
2. **14 → 13.** Кнопка «Назад» отправляет `'0'` и ожидает `L=0`; L4 гаснет.
3. **13 → 14.** Повторный шаг вперёд повторно включает L4; именно этот переход демонстрирует связь действия на экране с реальной периферией.
4. Пройдите оставшиеся шаги: в модели показывается бесконечный `JAL x0,0`, LED остаётся включённым.

### Задание H3. Автоматический режим и другие LED

Запустите автоматическое прохождение от начального состояния; убедитесь, что аппаратное действие привязано к шагу 14, а не к произвольному времени. Повторите на нескольких выбранных светодиодах. По окончании нажмите **«Отключить»**, затем остановите локальный сервер `Ctrl+C`.

**Принципиальная граница достоверности.** В HTML показаны **4 примерные инструкции** `LUI`, `ADDI`, `SW`, `JAL` и **19 педагогических событий**. В настоящей FPGA работает другая, **118-инструкционная** программа командного UART-контроллера. Браузер не останавливает ядро на каждой инструкции; при движении назад процессор **не обращает своё прошлое**, а получает *новую команду* выключения LED. Синхронизировано событие изменения выхода и подтверждение `L=n`, **не тактовое исполнение** внутреннего PicoRV32.

Не проводились исчерпывающие тесты ISA RV32I, оценка надёжности UART при помехах/потере байтов или плотном потоке команд, проверка на других платах и версиях Gowin, измерение токов LED, оптическое измерение свечения, запись в `embFlash`, потактовая трассировка процессора или аппаратная остановка на каждой из 19 учебных фаз. | HTML + FPGA | Ручное прохождение 19 шагов, автоматический режим, шаг назад выключает, шаг вперёд включает; повторено с **тремя** выбранными LED (их номера отдельно не записывались) | HTML_HARDWARE_PASS |

**Ресурсы PnR:** `1868` LUT/ALU/ROM16 = `1512 LUT + 356 ALU`; `767/6693` регистров (~12%); `1127/4320` CLS (~27%); BSRAM **12%**.  
**Временной отчёт:** 2154 пути, 1883 конечные точки; худший setup slack **+17,997 нс**, худший hold slack **+0,563 нс**. Условия: setup Slow 1,14 В / 85 °C; hold Fast 1,26 В / 0 °C.  
**Сформированный `.fs`:** `picorv32_nano9k.fs`, **3 558 473 байта**, 20.10.2026 09:14:59 по времени файла.  
**Граница подтверждения:** выводы команд приведены по протоколу испытания; зрительное наблюдение светодиодов и поведения HTML сообщено испытателем. Отдельный синхронный видеозапись/лог транзакций на уровне GPIO к материалам не приложен.

**Итоговый вывод:** поставленная функциональная задача выполнена. Система переводит действия студента в подтверждённые команды реальному процессору и воспроизводимые состояния физического LED. При этом образовательная последовательность из 19 шагов остаётся концептуальной моделью. Работу **LAB-02 v0.1.0** можно считать завершённой на заявленном уровне проверки; публикация изменений в GitHub является отдельной операцией и не утверждается данным протоколом.
