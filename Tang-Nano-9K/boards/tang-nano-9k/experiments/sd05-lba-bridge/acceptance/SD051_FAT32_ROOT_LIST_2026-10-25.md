# SD-05.1 — FAT32 filesystem access through Tang Nano 9K (25 October 2026)

**VERDICT: operator-confirmed hardware PASS for volume identification, ROOT-directory listing, and the nested `System Volume Information` directory through the existing SD-05 read-only block bridge. Reading file contents and multi-cluster FAT chain traversal remain untested.**

## Test configuration

- FPGA: Tang Nano 9K, previously hardware-qualified SD-05 bitstream.
- PC control: Python `tools/fat32_host.py` over **COM10**, SDHC CMD17 read-only; no FPGA RTL change, new bitstream, CMD24 or card write.
- Source tree: `boards/tang-nano-9k/experiments/sd05-lba-bridge`.
- Geometry previously checked from the SD-05 hardware-captured MBR/VBR/ROOT sectors, matching SD-03.

## Findings

1. PC interpreted real MBR and FAT32 BPB correctly through FPGA UART block reads: partition LBA **64**, FAT LBA **2112**, data and root initial LBA **17472**, cluster size **64 sectors**, **983007** data clusters.
2. FAT32 long filename parsing produced **System Volume Information**, an existing hidden/system directory (`ATTR=0x16`) starting at cluster **3**.
3. Root listing used **3 unique sector reads** (LBA0 MBR, LBA64 VBR, LBA17472 first ROOT sector). This particular test did not need to traverse a FAT chain or read file contents.
4. The log establishes success at the user/board interface; no byte-for-byte host block-device comparison or cross-card certification is claimed.

### Next bounded read-only physical test

```powershell
python $fat --port COM10 get '/System Volume Information/IndexerVolumeGuid' '.\sd051_IndexerVolumeGuid.bin'
Get-Item '.\sd051_IndexerVolumeGuid.bin' | Select-Object Name,Length
Get-FileHash '.\sd051_IndexerVolumeGuid.bin' -Algorithm SHA256
Get-Content -LiteralPath '.\sd051_IndexerVolumeGuid.bin' -Raw -Encoding Unicode
```

Output filename is new and `get` uses exclusive PC-side creation
(`xb`) to avoid overwriting existing files. It never writes to SD.
The last command interprets the expected Windows GUID text as UTF-16LE;
treat unexpected bytes or encoding separately rather than altering the
FPGA controller. On test failure, inspect the exact error before
reprogramming or making any RTL changes.

**Stop condition:** Once the 76-byte file is captured and verified, freeze
