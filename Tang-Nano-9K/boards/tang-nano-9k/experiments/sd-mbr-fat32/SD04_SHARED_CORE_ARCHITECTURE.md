# SD-04 — общая архитектура SDHC-ядра (проект, не новая прошивка)
**Дата: 24 октября 2026 · Статус: архитектурное решение / implementation pending**

## Инженерный принцип

SD-01, SD-02 и SD-03 остаются неизменяемыми воспроизводимыми снимками со своими `rtl/` и проверенными аппаратными квитанциями. Повторять копирование всего контроллера в каждый следующий эксперимент нецелесообразно. Следующий **новый** проект SD-04 использует один версионированный исходный SDHC SPI core как зависимость, а не очередную ручную копию.

## Подтверждённые строительные блоки

- `lab05_spi_byte` — один байт SPI mode 0, зарегистрированный SCK, 27 MHz.
- `lab05_sd_read_sector` — инициализация SDHC один раз, CMD17 по 32-битному LBA, 512 байтов в BSRAM, CRC16 и отдельные коды ошибок.
- `sd03_mbr_parser` — определение MBR-раздела.
- `sd03_fat32_bpb` — BPB/FAT32, последовательные арифметические шаги, проверка адресных границ.
- `sd03_volume_scanner` — планировщик двух чтений (MBR→VBR), вывод проверенных адресов FAT/DATA/ROOT.

На текущий момент SD-03 имеет самостоятельные копии нескольких модулей SD-02, а не ссылки на единый core. Версии `sd_read_sector.v` в SD-02 и SD-03 совпадают по blob SHA, но `spi_byte.v` отличается заголовком; это именно дублирование файлов, не отдельная разработка нового протокола.

Не создавать дубликаты `lab05_sd_read_sector` и `lab05_spi_byte` в SD-04. `build.ps1` / TCL SD-04 должны ссылаться на зафиксированную версию core из `cores/`; сборка должна хранить SHA исходников и присваивать сборке новый SHA .fs.

## Контракт для SD-04

- Вход: `read_start`, `read_lba[31:0]`.
- Выход: `busy`, `done`, `error_code[7:0]`, `peek_addr[8:0]`, синхронный `peek_data[7:0]`.
- Размер сектора: 512 байтов; следующую команду подавать только после успешного `done`; RAM-буфер перезаписывается при следующем CMD17.
- `SD-03` поставляет проверенные `first_fat_lba`, `first_data_lba`, `root_cluster`, `sectors_per_cluster`, `cluster_count`. В текущем top SD-03 часть параметров не выведена по UART, поэтому будущая точная интеграция должна передавать их по внутреннему интерфейсу.
- `SD-04` сначала читает первый сектор корневого каталога (в проверенной карте LBA **17472**), декодирует записи по 32 байта, различает удалённые / пустые / LFN; затем отдельно реализует FAT chain с защитой от циклов, bad-cluster, выхода за границы.
- Только **read-only**. Не менять файловую систему, карту, SD-01/02/03 или PiKoSoL v0.2.0.

## Gate перед интеграцией

1. Создать общую core-папку **из точно проверенного RTL** без функциональных изменений.
2. Icarus: повторить SD-02 SPI/CMD17/CRC и SD-03 MBR/BPB тесты; затем добавить тесты SD-04.
3. Проверить byte-for-byte source manifests и изменения интерфейсов.
4. Gowin PnR/STA + fingerprint bitstream SHA-256 для новой версии проекта. Нельзя автоматически переносить STA PASS SD-03 на SD-04.
5. SRAM-only board acceptance и UART-лог. Только после этого обсуждать интеграцию с PiKoSoL.

## Что эта запись НЕ означает

**Это дорожная карта и контракт, а не завершённая SD-04, и не новый hardware PASS.** Демонстрация HTML v2 — отдельный браузерный инструмент, читающий файлы на ПК локально, а не содержимое FPGA/SD по JTAG.
