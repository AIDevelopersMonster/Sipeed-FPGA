Раздел начинается с LBA 64. Зарезервированная область: 2112 − 64 = 2048 секторов. Совокупный размер размещённых FAT: 17472 − 2112 = 15360 секторов.

Что дальше в SD-04.3

Из записи каталога найден начальный кластер 3. Чтобы прочитать эту папку, потребуется вычислить её LBA по размеру кластера BPB и запросить новый CMD17.

Текущий UART не содержит значения SectorsPerCluster, поэтому адрес кластера 3 здесь не выдумывается.

Выбранная 32-байтовая запись

Почему «SYSTEM~1»?

FAT32 хранит короткое имя (SFN, формат 8.3) в основной записи. Длинное имя (LFN, UTF-16LE) может находиться в предшествующих записях с атрибутом 0F.

В аппаратном выводе подтверждены два LFN-фрагмента, но сами 26 возможных кодовых единиц UTF-16 не передавались. Поэтому полное имя System Volume Information пока лишь правдоподобная гипотеза.

HEX-инспектор и реальные бинарные файлы

Всё обрабатывается локально в браузере. Ни сеть, ни FPGA, ни SD-карта не изменяются.

Проверка образа: инструмент пытается прочитать MBR (LBA 0), затем VBR выбранного FAT32-раздела, извлечь параметры BPB и вычислить LBA корневого каталога. Для вашей карты аппаратный адрес — 17472. Если образ другой карты, адрес может отличаться. При выборе полного образа в память читаются только нужные срезы по 512 байтов.

Подтверждено и ещё не реализовано

Вопросы по эксперименту

Почему «две LFN» не доказывают полное имя System Volume Information?

Аппаратный протокол содержит только счётчик LFN=02. Для достоверного восстановления нужны сырые UTF-16LE символы, порядок фрагментов, контрольная сумма имени 8.3 и признак последнего фрагмента. При загрузке реального сектора HTML пытается провести эту проверку.

Почему у подкаталога размер SZ=0?

Для каталога FAT32 поле DIR_FileSize обычно равно нулю. Его содержимое определяется цепочкой кластеров, а не размером в этой записи.

Можно ли сразу читать файлы?

Пока нет. Чтение файлов требует поиска записи, перевода номера кластера в LBA и перехода по таблице FAT с обработкой маркеров конца цепочки, битых кластеров и границ тома.

HTML считывает карту непосредственно через USB?

Нет. Браузерный инструмент читает только выбранные вами локальные файлы через File API. Для прямого чтения с FPGA потребуется отдельный протокол передачи секторов через UART/USB.
