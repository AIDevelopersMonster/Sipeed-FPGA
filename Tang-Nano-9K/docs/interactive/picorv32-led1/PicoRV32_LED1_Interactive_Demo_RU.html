Важное ограничение модели: каждый шаг показывает смысловую микрооперацию и состояние интерфейсов; один шаг не обязательно равен одному такту реального PicoRV32. Настоящее ядро использует отдельные автоматы cpu_state и mem_state, синхронную ROM и зарегистрированный mem_ready. HTML не запускает Verilog и не моделирует задержки затворов FPGA.

1. Загрузочная ROM (тот же механизм, что в rtl/boot_rom.v)

Синтезатор реализует таблицу констант в ресурсах FPGA. Сигнал word_addr — это адрес слова, то есть младшие байтовые биты отброшены.


  
2. Фрагмент декодера vendor/picorv32/picorv32.v
decoded_rs1 <= mem_rdata_latched[19:15];
decoded_rs2 <= mem_rdata_latched[24:20];

// Сначала распознаётся семейство STORE по opcode.
is_sb_sh_sw <= (mem_rdata_latched[6:0] == 7'b0100011);

// Затем распознаётся SW по funct3.
instr_sw <= is_sb_sh_sw && (mem_rdata_q[14:12] == 3'b010);

  
Строки здесь объединены как учебная выдержка из разных участков декодера; они не являются готовым самостоятельным Verilog-модулем.

  
3. Настоящая адресная логика в rtl/picorv32_soc.v
wire is_mmio = (mem_addr[31:8] == 24'h200000);

// Внутри clocked always-блока:
if (mem_valid && !mem_ready) begin
    if (is_mmio) begin
        case (mem_addr[7:0])
            8'h00: begin
                if (|mem_wstrb && mem_wstrb[0])
                    leds <= mem_wdata[5:0];
                mmio_rdata <= {26'b0, leds};
                mem_ready <= 1'b1;
            end
        endcase
    end
end

assign led_n = ~leds;

  
4. Привязка вывода платы constraints/tang_nano_9k.cst
IO_LOC "led_n[0]" 10;
IO_PORT "led_n[0]" IO_TYPE=LVCMOS18;

  
Один и тот же SW работал бы с UART, RAM или другой периферией; устройство определяется **адресом**, который декодирует SoC. GPIO L1 является частью нашей интеграции, а не частью стандартного ядра PicoRV32.
