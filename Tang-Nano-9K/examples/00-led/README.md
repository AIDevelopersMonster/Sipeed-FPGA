# LAB-00 — первая самостоятельная схема на Tang Nano 9K

**Статус: PREPARED / RTL, Gowin BUILD и BOARD ещё не проверялись для этого проекта.**
Ниже — кандидат для учебного эксперимента. Не публикуйте его как работающую прошивку, пока не пройдены тесты.

[← Первый запуск с готовой PiKoSoL](../../START_HERE_RU.md) · [Дорожная карта](../../ROADMAP_RU.md) · [Реестр проверенных сборок](../../VERIFIED_BUILDS.md)

## Что делаем

Пишем простую аппаратную схему на **Verilog**, не используя CPU, HDMI, UART или дополнительные модули. На шести встроенных LED по очереди горит один светодиод. Каждые **13 500 000** тактов генератора **27 МГц** активный светодиод меняется (около 0,5 секунды). После сброса последовательность начинается с LED[0].

Модель показывает, что FPGA исполняет не последовательность инструкций микроконтроллера, а созданную вами цифровую схему: регистр-счётчик, сравнение, регистр состояния и декодер шести выходов.

## Понадобится

- Tang Nano 9K (GW1NR-9C), USB-C кабель передачи данных, Windows 10/11 и PowerShell 7;
- Gowin EDA Education с `gw_sh.exe` и Gowin Programmer для сборки и записи в **SRAM**;
- необязательно Icarus Verilog (`iverilog` и `vvp`) для отдельного RTL-теста;
- не требуются HDMI, USB-UART терминал, microSD и внешние PMOD.

**Внимание:** это специально новая LAB-00 и пока **не аппаратно подтверждённая сборка**. Если хочется сразу увидеть работающий результат, начните с [PiKoSoL v0.2.0](https://github.com/AIDevelopersMonster/Sipeed-FPGA/releases/tag/pikosol-v0.2.0).

## Что находится в каталоге

| Файл | Назначение |
| --- | --- |
| `rtl/lab00_led_top.v` | счётчик, управление LED, асинхронный активный низкий сброс |
| `constraints/lab00_led.cst` | проверявшееся в других проектах соответствие выводов платы |
| `constraints/lab00_led.sdc` | ограничение 27 МГц |
| `tb/lab00_led_tb.v` | проверка 12 переходов, замыкания кольца и сброса |
| `test.ps1` | RTL-симуляция на ПК без FPGA |
| `build.tcl`, `build.ps1` | изолированная сборка через Gowin без программирования |
| `program_sram.ps1` | отдельный dry-run и добровольная SRAM-загрузка |

Выводы: тактирование **pin 52 / LVCMOS33**, `reset_n` **pin 3 / LVCMOS18**, `led_n[0..5]` **pins 10, 11, 13, 14, 15, 16 / LVCMOS18**. LED работают по **низкому уровню**. Электрические назначения взяты из [проверенной обвязки PicoRV32](../../01-PicoRV32/constraints/tang_nano_9k.cst), однако конкретный битстрим LAB-00 ещё не проверен. В старых материалах название кнопки на pin 3 встречается как S1 и S2 — на плате требуется подтвердить маркировку и поведение, вместо угадывания.

## Шаг 1 — получить исходники

```powershell
git clone https://github.com/AIDevelopersMonster/Sipeed-FPGA.git
Set-Location .\Sipeed-FPGA\Tang-Nano-9K\examples\00-led
```

Если репозиторий уже есть, не клонируйте поверх него: просто перейдите в `Tang-Nano-9K\examples\00-led` внутри своей рабочей копии.

## Шаг 2 — проверить Verilog (необязательно, желательно)

```powershell
.\test.ps1
```

Ожидаемая строка при успешном запуске теста: `LAB00_RTL_SIM_PASS`. Это **только симуляция**, не приёмка платы.

## Шаг 3 — синтез, PnR и создание .fs

```powershell
.\build.ps1
```

Если Gowin установлен в другом месте:

```powershell
.\build.ps1 -GowinRoot 'C:\Gowin\Gowin_V1.9.9Beta-4_Education'
```

Сборка изолирована в новом каталоге `%TEMP%\TN9K_LAB00_BUILD_...`; исходники репозитория, Flash и ранее подтверждённые проекты не изменяются. При успехе скрипт выведет `LAB00_CANDIDATE`, `LAB00_SHA256` и путь лога.

**Перед программированием** проверьте полный отчёт синтеза, PnR, временные ограничения 27 МГц и принадлежность всех выводов правильным банкам. Успех `gw_sh` ещё не является ни Timing PASS, ни BOARD PASS.

## Шаг 4 — только временная SRAM, после проверки отчёта

Подставьте **фактический** путь, который вывел `build.ps1`; не копируйте случайный путь из интернета.

```powershell
$fs = 'C:\путь\из\LAB00_CANDIDATE\tang_nano9k_lab00_led.fs'
.\program_sram.ps1 -Bitstream $fs
# Только если проверили файл, отчёты и устройство:
.\program_sram.ps1 -Bitstream $fs -Program
```

Команда без `-Program` лишь показывает файл и его SHA-256. В обоих скриптах отсутствуют команды записи Flash. После выключения питания SRAM-прошивка теряется; возвращение к заводскому состоянию не обещается автоматически без проверки стартовой конфигурации.

## Шаг 5 — наблюдение на плате и критерии приёмки

1. Идентификатор программатора соответствует **GW1NR-9C**, SRAM Program сообщает успешное завершение.
2. Горит ровно один из шести пользовательских LED; примерно каждые 0,5 секунды включается следующий.
3. После шестого LED повторяется первый.
4. Замыкание `reset_n` на низкий уровень и последующее отпускание возвращает последовательность к первому LED. **Физическую кнопку проверьте по pin 3, не полагайтесь на противоречивые исторические подписи S1/S2.**

После реального наблюдения сохраним дату, полный путь/хеш `.fs`, Gowin-отчёт, наблюдения и фото либо видео. Лишь затем можно обозначить **LAB-00 BOARD PASS** и внести конкретный образ в [реестр](../../VERIFIED_BUILDS.md).

**Правило:** созданный RTL ≠ симуляция ≠ удачная сборка ≠ успешная прошивка ≠ подтверждённая работа.
