# PiKoSoL TP20 — запуск после скачивания GitHub ZIP

**Плата:** Tang Primer 20K Dock (GW2A-18C). **ОС:** Windows. **Режим:** FPGA SRAM only; Flash не записывается.

## Для нового пользователя

1. Скачать [ZIP репозитория](https://github.com/AIDevelopersMonster/Sipeed-FPGA/archive/refs/heads/main.zip) и распаковать его. Не запускать файлы непосредственно из окна ZIP.
2. Открыть каталог `Tang-Primer-20K/Examples/PR20-03-PiKoSoL-KonSol`.
3. Установить Python 3 с Tkinter, пакет `pyserial` (`python -m pip install pyserial`), Gowin Programmer. Подключить Tang Primer 20K Dock, HDMI и USB-UART. Закрыть MobaXterm и другие программы, занимающие COM-порт.
4. Запустить **`START_PiKoSoL.cmd`** двойным щелчком; указать COM-порт (например, COM10) и выбрать режим:
   - **1 — полный запуск:** программирование только SRAM прошивкой `firmware/PiKoSoL_TP20_SD01_RO.fs`, затем XMODEM-загрузка `monitor.bin` и открытие File Manager.
   - **2 — загрузка монитора:** если HDMI показывает `Waiting for downloader ...`, FPGA повторно не программируется. Передаётся `monitor.bin`, затем открывается File Manager.
   - **3 — только File Manager:** если монитор уже работает и показывает `PiKoSoL>`. COM-порт не открывается до действия пользователя в GUI.
5. В режиме 1 `START_PiKoSoL.py` использует **уже включённый в GitHub ZIP файл** `firmware/PiKoSoL_TP20_SD01_RO.fs`. Автоматической загрузки отсутствующего `.fs` из THLN33 или другого источника **нет**: если файл отсутствует либо не проходит проверку, запуск останавливается до программирования FPGA. Контрольные значения: **7 264 150 байт**, **SHA256 `900C95DC8575C31EBD3E01F61A64F99A8BBA14358A0C0DB20110140B27C89D28`**. В режимах 2/3 FPGA-прошивка не изменяется.
6. **Обязательно дождаться `COM OPEN PASS COM10 115200 8N1` и строки `*** ACTION REQUIRED: PRESS DOCK S0 NOW ***`. Только после этого нажать кнопку Dock S0 один раз.** FPGA посылает символ `C` однократно после сброса: если нажать S0 до открытия COM, загрузчик пропустит момент передачи. Скрипт теперь ожидает `C` без 18-секундного тайм-аута, каждые 20 секунд напоминает о S0. Если сообщение не меняется, можно нажать S0 повторно; `Ctrl+C` прерывает ожидание без записи Flash. После `BOOTLOADER_C_PASS`, XMODEM ACK и `MONITOR_BOOT_PASS` ПК-программа закрывает COM10 и **только затем** запускает File Manager.


**File Manager v0.2.0 (GitHub BIN catalog candidate):** после открытия GUI нажмите «Получить список», выберите опубликованный `.bin`, затем «Скачать выбранный». Проверка точного размера, SHA256 и заголовка PKD1 обязательна. Скачивание **не** выполняет загрузку в FPGA; команда «Загрузить .bin + RUN» остаётся отдельным решением оператора. Модуль каталога и манифест расположены в `FileManager/`. Доказательств нового BOARD PASS этой версии пока нет.

**Проверка без аппаратных операций:** команда `--check` проверяет наличие обязательных файлов, SHA256 `monitor.bin` и `demo.bin`, самопроверку File Manager и указанные размер/SHA256 SD01 RO. COM-порт и FPGA не открываются.

```powershell
python .\START_PiKoSoL.py --check
```

**Запуск с явными параметрами (например, для диагностики):**

```powershell
python .\START_PiKoSoL.py --port COM10 --mode boot
python .\START_PiKoSoL.py --port COM10 --mode gui
```

Номер порта не универсален: COM10 — лишь пример. Выбранный COM передаётся в File Manager. Скорость UART — 115200 8N1.

**Ограничения и сохранность.** Выбор SD01 RO в автозагрузчике не является подтверждением аппаратной работы SD/FAT32 или совместимости этого `.fs` с прежним `monitor.bin`: полную цепочку проверяет оператор. После RAM-загрузки монитор не сохраняется при полном отключении питания. Известные `monitor.bin` и `demo.bin` проверяются по SHA256, не перезаписываются. Программирование `--run 2` меняет только текущую энергозависимую конфигурацию FPGA, поэтому при проверке экспериментальной DDR3-сборки используйте режим 2 или 3, а не 1. GUI и приложения остаются отдельно от встроенной в FPGA файловой системы: файлы передаются в RAM; FAT32 и DDR3 в основном проекте пока не заявлены как испытанные.

**Статус (23.11.2026):** Python-автозагрузчик переключён с GPIO V3714 на уже опубликованную `PiKoSoL_TP20_SD01_RO.fs`, её размер и SHA256 сверены с файлом в GitHub. Это изменение **конфигурации автозапуска, а не исходников RTL**; старый `.fs` остаётся в репозитории. Ранее после `SRAM PROGRAM PASS` наблюдалась ошибка `No XMODEM-CRC handshake C received`; исправленная последовательность предусматривает ожидание `COM OPEN PASS` и только затем нажатие Dock S0. Полный аппаратный запуск нового сочетания `.fs`/монитора пока не подтверждён (не BOARD PASS). GitHub Release не создавался.
