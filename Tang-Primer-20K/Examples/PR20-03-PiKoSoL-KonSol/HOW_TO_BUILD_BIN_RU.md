# PiKoSoL TP20 — как написать собственную программу и получить .bin

**Проверенная платформа:** Sipeed Tang Primer 20K Dock / Gowin GW2A-18C / PicoRV32 RV32I, тактирование 60 МГц. Монитор и File Manager v0.1.4 протестированы на реальной плате; изображения HDMI GRID получены аппаратно. Новые пользовательские программы требуют отдельной проверки BOARD PASS.

## Что уже доступно

- Записывать символы ASCII, цветной текст, рамки и цветовые полосы в HDMI текстовый экран 96x42.
- Выполнять простые циклы и запись 32-битных слов на нативном RV32I.
- Запускать отдельные приложения через File Manager -> UART COM10 (115200 8N1) -> XMODEM-CRC -> `LOAD`/`RUN`, не меняя FPGA-конфигурацию.
- Возвращаться из приложения в монитор через `jalr x0, 0(ra)` (RET).
- Генерировать демонстрационные экраны LCD 20x4 / RGB WS2812 / AUDIO PT8211 **на HDMI**. Эти три приложения НЕ управляют физическими периферийными модулями.

Нет автономного Python на FPGA, готовой ОС, сети, поддержанной SD-файловой системы, подключённого к CPU физического LCD/WS2812/PT8211 и проверенной процедуры сборки произвольных C-приложений.

## Какой язык используется сегодня?

Сейчас исходники пяти программ написаны на **Python** как *генераторы машинного кода*. Python запускается на ПК и непосредственно кодирует инструкции RISC-V RV32I:

- [`FileManager/build_tp20_apps.py`](FileManager/build_tp20_apps.py): функции `Screen.text()`, `rectangle()`, `bar()`, `clear()`; генератор инструкций `LUI`, `ADDI`, `SW`, `BNE`, `RET`.
- [`FileManager/build_hello_rv32i.py`](FileManager/build_hello_rv32i.py): минимальный пример генератора цветной надписи, параметр `--text`.
- [`FileManager/generated/`](FileManager/generated/): пять готовых проверенных образов `.bin` с SHA256.

**В FPGA исполняется не Python, а 32-битные машинные инструкции RISC-V.** Отдельный компилятор GCC для этих пяти программ **не использовался**.

## Самый простой собственный .bin: HELLO

Требуется Python 3, Windows PowerShell и уже скачанный с GitHub рабочий комплект в `Downloads\PiKoSoL_TP20_From_GitHub`. Сохраняем результат отдельно от пяти проверенных оригиналов:

```powershell
$root = "$env:USERPROFILE\Downloads\PiKoSoL_TP20_From_GitHub"
$out = "$env:USERPROFILE\Downloads\PiKoSoL_MyBIN\HELLO_MY_TP20.bin"

python "$root\FileManager\build_hello_rv32i.py" `
  --demo "$root\firmware\demo.bin" `
  --text "PRIVET PIKOSOL!" `
  --output "$out"
```

Это **сборка на ПК**, без COM, без перепрограммирования FPGA и без Flash. Скрипт сверяет SHA256 рабочего `demo.bin`, создаёт код RV32I и записывает `HELLO_MY_TP20.bin`. Текст в этом примере должен быть **ASCII**, кириллица текущим генератором не поддерживается.

Результат пока **CANDIDATE**. Чтобы проверить на железе, открой File Manager, выбери `HELLO_MY_TP20.bin`, посмотри его параметры, затем нажми «Загрузить .bin + RUN». Проверь HDMI и возвращение в `PiKoSoL>`. Не занимай COM10 другим клиентом одновременно.

### Создать сразу все пять демонстрационных .bin повторно

```powershell
$root = "$env:USERPROFILE\Downloads\PiKoSoL_TP20_From_GitHub"
python "$root\FileManager\build_tp20_apps.py" `
  --demo "$root\firmware\demo.bin" `
  --out "$env:USERPROFILE\Downloads\PiKoSoL_MyBIN\FiveApps"
```

Полученные файлы должны соответствовать алгоритму исходного генератора. Для сверки с опубликованной рабочей сборкой используй [манифест SHA256](working-manifest.json). Данный пример ничего не перезаписывает в папке `FileManager/generated`.

## Как описывается экран программой

В `build_tp20_apps.py` используется высокоуровневый Python-интерфейс, который генерирует RV32I машинные инструкции:

```python
s = Screen("MY_APP")
s.text(10, 12, "HELLO FROM RV32I", fg=YELLOW, bg=NAVY)
s.rectangle(10, 15, 40, 3, bg=TEAL)
s.bar(10, 19, 25, bg=LIME)
machine_code = s.close()
```

Этот фрагмент иллюстрирует **внутренний интерфейс генератора**, а не программу, исполняемую Python на плате. Для нового сценария добавляют функцию в копию исходного генератора и формируют контейнер `PKD1` по описанному ниже ABI. Исходные рабочие файлы не меняют.

## Устройство бинарного файла PKD1

Сначала 16 байт заголовка, затем машинные инструкции RV32I (little-endian):

| Смещение | Тип | Значение |
|---|---|---|
| 0x00 | uint32 LE | `0x31444B50` (байты `50 4B 44 31`, ASCII `PKD1`) |
| 0x04 | uint32 LE | Полный точный размер **всего** файла в байтах, включая 16-байтный заголовок |
| 0x08 | uint32 LE | Адрес входа `0x2000C010` |
| 0x0C | uint32 LE | `0` — резерв |

- Приложение загружается в RAM с адреса `0x2000C000`, код начинается по `0x2000C010`.
- Выделенное окно: 16 КиБ (`0x2000C000–0x2000FFFF`), однако текущая команда `LOAD` монитора принимает **не более 0x3000 байт (12 КиБ), включая дополнение XMODEM до кратности 128**.
- В пользовательском коде примеров сохраняются `ra` (`x1`) и `sp` (`x2`); возврат происходит через `RET`.
- Голый `.bin` без PKD1, обычный ELF, `.fs` для FPGA или стандартный файл из стороннего THLN33 загрузчика не являются взаимозаменяемыми.

## HDMI / видео MMIO

Текстовая видеопамять начинается с `0x30000000`. Каждая ячейка занимает 4 байта:

```text
address(x,y) = 0x30000000 + 4 * (y * 96 + x)
word = (foreground << 24) | (background << 16) | (mode << 8) | ASCII
```

В примерах `mode=0`, координаты `0<=x<96`, `0<=y<42`, индексы цветов 0–15. Для записи нужны 32-битные инструкции `SW`. Генератор использует адрес и значения и строит из них `LUI`/`ADDI`/`SW`.

## Может ли быть язык C или ассемблер?

**Да, архитектура RV32I это допускает**, но для собственной C-программы нужен отдельный и пока не проверенный на данной плате toolchain: `riscv32-unknown-elf-gcc` или аналог, флаги `-march=rv32i -mabi=ilp32`, freestanding runtime, собственный linker script (entry `0x2000C010`), безопасный stack, экспорт *raw machine code* через `objcopy -O binary`, упаковка в PKD1 и аппаратный тест. Просто переименовать `.elf` в `.bin` нельзя. Работа с `printf`, `libc` и `malloc` не следует автоматически из наличия процессора.

В будущем удобная цепочка: **редактор C/ASM → кросс-компилятор → ELF → objcopy → PKD1 + проверки → File Manager → XMODEM → PicoRV32**. До аппаратной проверки этот путь обозначаем как экспериментальный, не как BOARD PASS.
