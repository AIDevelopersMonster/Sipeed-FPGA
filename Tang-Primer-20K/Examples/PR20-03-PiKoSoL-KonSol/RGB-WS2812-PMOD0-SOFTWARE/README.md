# PiKoSoL TP20 — встроенный WS2812 через PMOD0, без новой конфигурации FPGA

**BOARD PASS, 22 ноября 2026 года** — пользователь подтвердил на реальной плате работу программного RGB-теста. Работающий объект: **Sipeed Tang Primer 20K + Dock V3714**, `PiKoSoL GPIO V3714` (идентификатор `GP14`), **PicoRV32 / RV32I**, HDMI и UART. В исходный FPGA-проект ничего не добавлялось: **существующий GPIO используется как ресурс процессора**.

**Отчёт о результатах:** передача GRB-кадров и реакция встроенного RGB WS2812 физически подтверждены оператором фразой «всё работает». Отдельного осциллографического измерения длительностей HIGH/LOW на T9 не проводилось; параметры импульсов и устойчивость при изменённых частотах нельзя считать полностью электрически аттестованными.

**Видеообложка:** [RGB без перепрошивки FPGA](media/rgb_without_fpga_reflash.jpg) — иллюстрация, **не** фотография испытательного стенда и не источник данных о распиновке.

## 1. Что делает работающая программа

| Файл | Статус / назначение |
|---|---|
| [`bin/TP20_RGB_VIA_PMOD0_SOFTWARE_TEST.bin`](bin/TP20_RGB_VIA_PMOD0_SOFTWARE_TEST.bin) | **BOARD PASS (по сообщению оператора)**: красный → зелёный → синий → выключение, приблизительно по секунде |
| [`src/build_rgb_pmod0.py`](src/build_rgb_pmod0.py) | Точный генератор RV32I-образа, из которого получен этот BIN |
| [`src/rv32i_assembler.py`](src/rv32i_assembler.py) | Локальная библиотека ассемблера для PKD1/XMODEM |
| [`src/test_rgb_pmod0.py`](src/test_rgb_pmod0.py) | 7 автономных проверок, включая эмуляцию MMIO и возврат в PiKoSoL |
| [`SHA256SUMS.txt`](SHA256SUMS.txt) | Контрольные суммы опубликованных файлов |

Программа не является отдельной FPGA-прошивкой: это **приложение в RAM**, запускаемое монитором `PiKoSoL` с помощью File Manager и команды `RUN`. Загрузка приложения не изменяет ни `.fs`, ни заводскую Flash.

## 2. Схема управления ресурсом

```text
Приложение RV32I (RAM / PiKoSoL)
    |
    +--> MMIO PMOD0_OUT 0x80000000
              |
              +--> старый top-level: pmod0 = ~port_out
                         |
                         +--> PMOD0[1] = FPGA T9
                                      |
                                      +--> встроенный WS2812 DIN
```

**Провод T9 общий:** он также обозначен как `PMOD0[1]` на GPIO-разъёме. Это **один физический ресурс**, а не два независимых. При работе WS2812 внешнее устройство, подключённое к PMOD0[1], получит тот же сигнал; не следует включать одновременно конфликтующие выходы.

| Адрес | Значение | Назначение |
|---|---|---|
| `0x80000000` | `PMOD0_OUT` | Старая восьмибитная защёлка GPIO; `1` в бите 1 даёт **LOW** на T9 из-за инверсии `~port_out` |
| `0x8000005C` | `GPIO_ID` | Проверка `0x47503134` (`GP14`) перед изменением GPIO/тактовой частоты |
| `0xE0000008` | `CLKREG` | Временный выбор `2` (приблизительно 60 МГц CPU), затем восстановление прежнего значения |

Программа формирует все 24 бита WS2812 последовательно в порядке **GRB, MSB-first**. Каждый бит состоит из двух операций записи `sw` в PMOD0_OUT и пауз из инструкций RV32I `nop`. Между кадрами есть низкий RESET/защёлка. Передача **программная**: отдельного WS2812-RTL и нового RGB-MMIO не требуется.

### Почему у нас это получилось без специальной `.fs`

Ранее мы уже сделали **универсальный программно доступный GPIO**. Адресный светодиод — устройство на существующей линии FPGA, поэтому программу можно изменить, не перепроектируя кристалл. Добавлять новый специализированный аппаратный блок оправданно только при доказанном ограничении доступного пути (например, точность тайминга или необходимость параллельной работы устройств).

## 3. Запуск на плате

1. Оставить **проверенную** конфигурацию `PiKoSoL GPIO V3714` и работающий `monitor.bin`; **не** загружать отдельную RGB `.fs`.
2. При выключенном питании освободить `PMOD0[1]` от внешней нагрузки с конфликтующим драйвером. Встроенный WS2812 остаётся подключён к T9.
3. В `PiKoSoL File Manager` выбрать [`TP20_RGB_VIA_PMOD0_SOFTWARE_TEST.bin`](bin/TP20_RGB_VIA_PMOD0_SOFTWARE_TEST.bin), нажать **«Загрузить .bin + RUN»**. Размер — **11 772 байта**, 92 блока XMODEM.
4. Наблюдать смену цветов встроенного RGB. Через HDMI/COM видны диагностические строки; после OFF программа восстанавливает исходный `CLKREG` и возвращает управление монитору.
5. После успешной загрузки запуск можно повторить одной командой `RUN` без повторного XMODEM. При неуспешном `LOAD` не выполнять `RUN` над частично перезаписанным кодом.

Программа сохраняет семь бит `PMOD0_OUT`, не относящихся к RGB. Бит 1 оставляется в положении физического **LOW** после OFF, чтобы обеспечить корректную паузу WS2812.

## 4. Воспроизводимость

Из каталога `src` (Python 3):

```powershell
python -B .\test_rgb_pmod0.py
python -B .\build_rgb_pmod0.py
Get-FileHash .\TP20_RGB_VIA_PMOD0_SOFTWARE_TEST.bin -Algorithm SHA256
```

**7/7 offline PASS** (валидность PKD1, порядок битов GRB, RESET/OFF, эмуляция команд и MMIO, охрана `GPIO_ID`, восстановление `CLKREG`, постоянная длина битовых последовательностей). Повторная сборка дала *побайтно тот же* `TP20_RGB_VIA_PMOD0_SOFTWARE_TEST.bin`:

```text
SHA256 136F49B22E55F95B9ABEEBCA89162940C7449545C47B0B61EA6FF357FA578F78
```

В исходном генераторе и автономных тестах сохранены исторические строки `CANDIDATE` / `BOARD-UNVERIFIED`, написанные **до аппаратной проверки**. Эти строки не описывают нынешний статус: пользователь впоследствии подтвердил физическую работу на плате. При этом программные тесты **не заменяют** осциллографическую проверку временных параметров WS2812.
