# PR25-KonSol-DVI — цветная псевдографика, Tang Primer 25K

**Статус: BUILD PASS / SRAM VIDEO BOARD PASS (15.11.2026, фото оператора).** Небольшой самостоятельный **статический** демонстрационный проект, не отдельный релиз и не полноценный файловый менеджер.

**Что видно:** 640×480, сетка 80×30 ячеек 8×16, двухпанельный экран «KonSol Commander 25K», цветные имена файлов, псевдографические границы, тест цвета RGB. Текст и перечень файлов **зашиты в RTL**, никаких реальных дисковых операций, команд UART и CPU нет.

**Что наше:** `lab_top_konsol.sv` — собственный комбинаторный RGB/символьный генератор. **Что чужое:** закрытый `DVI_TX_Top` производителя GOWIN, PLL и проверенная обвязка/генератор кадров исходной учебной лаборатории. [Руководство по заводскому IP](../../../ip/hdmi/gowin-dvi-tx/README.md). Наша программа не является «заводской прошивкой платы».

## Подключение

- Tang Primer 25K + Dock, GOWIN 1.9.9Beta-4.
- **PMOD DVI оставить в разъёме непосредственно под USB-A** — там аппаратно получено изображение. Положение проверено, не менять.
- Монитор подключить HDMI-кабелем к PMOD DVI.
- FPGA-пары TMDS: clock H5/J5; D0 H8/H7; D1 G7/G8; D2 F5/G5.
- Запись: только **SRAM** (Gowin Programmer `--run 2`). Конфигурационная Flash не используется. SDRAM, USB-клавиатура, SD-карта не требуются.

## Файлы этого примера

```text
PR25-KonSol-DVI/
  README.md
  Upload_Trial_Artifacts.ps1       # однократная публикация локальных проверенных файлов
  rtl/
    lab_top_konsol.sv              # появится после загрузки с операторского ПК
  build/
    Build_KonSol_Trial.ps1         # появится после загрузки с операторского ПК
  fs/
    pr25_konsol_trial.fs           # появится после загрузки с операторского ПК
    sha256.txt                     # SHA256 рабочего .fs
    README.md
```

**Важно:** исходные файлы и бинарник **ещё не загружены**, поскольку подтверждённый `.fs` находится в `%TEMP%` на Windows-компьютере оператора. До их появления эта страница — паспорт результата, а не готовый комплект для воспроизведения. Никаких заглушек `.fs` не создаётся. Сборочный скрипт из локального архива должен сопровождать исходник: он использует внешний учебный upstream и локальную проверенную сборку, что здесь явно указано.

## Однократное размещение файлов в этот же каталог GitHub

На **том ПК, где был запущен эксперимент**:

```powershell
$upload = "$env:TEMP\Upload_Trial_Artifacts.ps1"
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/AIDevelopersMonster/Sipeed-FPGA/main/Tang-Primer-25K/Examples/PR25-KonSol-DVI/Upload_Trial_Artifacts.ps1' -OutFile $upload
& $upload
```

Нужны авторизация `gh auth login` и три локальных файла: `%TEMP%\PR25_KonSol_Package\lab_top_konsol.sv`, `Build_KonSol_Trial.ps1` и `%TEMP%\PR25_KonSol_LocalTrial\impl\pnr\pr25_konsol_trial.fs`. Сценарий сначала проверяет файлы и SHA256 и **не перезаписывает** одноимённые GitHub-файлы.

**Сборка:** первоначально использовала локально сохранённый исходный Gowin Tcl/PLL/CST и заменяла только `lab_top.sv` нашим генератором. Если начальные материалы будут удалены с компьютера, для воспроизведения потребуется заново создать исходный DVI_TX из EDA и собрать сопоставимый wrapper; не считать локальный скрипт полностью автономным.
