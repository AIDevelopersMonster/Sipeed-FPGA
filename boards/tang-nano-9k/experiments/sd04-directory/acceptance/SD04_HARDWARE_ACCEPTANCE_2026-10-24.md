## Точный UART оператора

```text
SD03 RESULT=MBR_FAT32    VOL=00000040 FAT=00000840 DATA=00004440 ROOT=00004440 CLUS=000EFFDF E=00
SD04 ROOT=00004440 VOL=00000040 FAT=00000840 E=00
SD04 IDX=02 K=D NAME=SYSTEM~1.    A=16 CL=00000003 SZ=00000000
SD04 END FILE=00 DIR=01 LFN=02 SKIP=00 STOP=01
```

Первая строка начинается `SD03 RESULT=` и относится к формату сообщения **предыдущего SD-03**. Текущий `sd04_directory_probe_top` выдаёт только сообщения `SD04 ...`. Поэтому строку SD-03 следует сохранять как предоставленный контекст терминала, **но не приписывать новой SD-04 прошивке**.

## Разбор фактически полученных строк SD-04

| Поле | HEX / значение | Вывод |
|---|---|---|
| ROOT | 00004440 | первый сектор корневого каталога, LBA 17472 |
| VOL | 00000040 | начало раздела FAT32, LBA 64 |
| FAT | 00000840 | начало первой FAT, LBA 2112 |
| E | 00 | считыватель не зарегистрировал ошибку при обнаружении тома и чтении сектора каталога |
| IDX | 02 | запись с индексом 2 (третья запись 32 байта в секторе) |
| K | D | каталог |
| NAME | SYSTEM~1 | короткое имя FAT32 (8.3); пробелы окончания поля показаны как в UART |
| A | 16 | атрибут 0x16: DIRECTORY(0x10) + SYSTEM(0x04) + HIDDEN(0x02) |
| CL | 00000003 | начальный кластер каталога 3 |
| SZ | 00000000 | размер каталога в записи 0; для каталога допустимо |
| FILE | 00 | обычных 8.3 файлов не распознано до конца активных записей первого сектора |
| DIR | 01 | распознан один подкаталог |
| LFN | 02 | две записи длинного имени обнаружены, но **не декодированы** |
| SKIP | 00 | других пропущенных элементов нет |
| STOP | 01 | обнаружена первая неиспользованная запись (0x00) |

Весь вывод согласуется с каталогом **System Volume Information**, у которого DOS-алиас может выглядеть как `SYSTEM~1`. Однако полное имя в этой версии **не подтверждено аппаратным декодированием LFN**: оно является вероятной интерпретацией, не фактом эксперимента.

## Итог доказанной функциональности

FPGA обнаружила FAT32 том через MBR/VBR, вычислила стартовый LBA корневого каталога, затем запросила по нему дополнительный CMD17, считала 512-байтовый сектор в BSRAM, проанализировала 32-байтовые записи и вывела одну настоящую запись каталога по UART. Базовый SPI/SDHC core не был переписан; сохранён read-only режим.

**Не доказано:** побайтовое совпадение всего сектора с независимым дампом ПК; восстановление Unicode LFN; чтение подкаталога из кластера 3; обход цепочки FAT; чтение содержимого файлов; универсальная поддержка нескольких карт и exFAT/GPT; полный external SD MISO timing sign-off. Встроенный отчёт UART не заменяет независимую аппаратную трассу и программаторный лог.
