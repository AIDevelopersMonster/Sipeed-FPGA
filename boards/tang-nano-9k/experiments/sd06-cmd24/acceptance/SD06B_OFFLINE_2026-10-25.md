The 9 Python tests verify in-memory authorization/identity/preimage guards,
frame encoding/decoding, checksum rejection, size and boundary checks.

The test script separately compiles the engine with the **real**
`lab05_spi_byte` interface and runs the byte-model testbench with a mock
of that interface. The mocked card checks the CMD24 command bytes,
512-byte payload, CRC16, response token, R1 failures, response/busy
timeouts and authorization guard inputs.

## Strict acceptance boundary

This is not a physical-card or write-capable FPGA PASS. The standalone RTL
has **no board top, UART receive-frame integration, trusted preimage SHA
comparison, card identity check, SPI read/write arbitration, CMD17 readback,
confirmed allowlisted scratch LBA, Gowin build, or STA**. The current
`authorized` signal is a testbench input, not an authenticated hardware
authorization. The existing SD-05 read-only bitstream remains frozen.

No physical write-capable firmware should be created or programmed until
the SD-06C interface is end-to-end validated with negative tests. SD-06D
requires user-explicit disposable-medium authorization and verified backup.
