# Sipeed Tang Nano 9K — профиль платы (BSP)

**Статус:** первая реально испытанная FPGA-платформа проекта. [Самостоятельные реализации](experiments/README.md) находятся в `experiments/`. Это **не новая копия PiKoSoL** и **не отдельный Git-репозиторий**. Каталог создаётся без переименования/переноса проверенных файлов LAB-04 и LAB-05.

## Что живёт здесь

- `board.json`: идентификатор платы, точная модель FPGA, тактовая частота, проверенные назначения сигналов и их статус. Это **паспорт наблюдаемых аппаратных свойств**, пока не генератор CST/SDC.
- В будущих ревизиях: только сведения и адаптеры, уникальные для платы (распиновка, PLL, IO-банки, периферийные микросхемы, внешняя память, правила программирования).
- Физическая маркировка кнопки перезапуска проверенного SD-зонда — **S2**, signal `reset_n` FPGA pin 3. Не ориентироваться на спорную S1/S2 нумерацию из разных обозначений схемы.

## Чего здесь не должно быть

Профиль платы не должен сам становиться общей библиотекой IP. Однако отдельные исследования в `experiments/` **могут содержать собственные снимки HDL, тестов и сборочных скриптов** с зафиксированным происхождением. Такие копии развиваются как частные случаи и не подменяют канонические общие компоненты.

**Для разных плат генерируются разные FPGA-конфигурации `.fs`.** Прошивка для PicoRV32, по возможности, собирается из общих исходников и узнаёт доступные устройства через стабильный MMIO-контракт (его расширение для SD ещё не утверждено).

## Существующие сборки остаются на своих местах

- LAB-04.3.2 / LAB-04.4: `01-PicoRV32/lab04/` — аппаратно проверенный PiKoSoL v0.2.0.
- LAB-05.1: `01-PicoRV32/lab05/` — аппаратно проверенный независимый SD-зонд; **FAT32 в PiKoSoL ещё нет**.
- Новые платформенные обёртки будут появляться в `targets/<board-id>/` **внутри активной конфигурации SoC**. Сначала создаём параллельную сборку, проверяем эквивалентность, затем прекращаем использовать старые пути; проверенные снимки LAB-04/05 не передвигаем.

## Правило второй платы

Добавление 20K/25K начинается с **точного названия и ревизии конкретной платы**. Различаются не только LUT: реальные RAM/PSRAM/SDRAM, частоты, PLL, HDMI, GPIO, SD-слот, JTAG, IO-напряжения и инструментальные ограничения. До проверки нельзя создавать фиктивный профиль `nano20k` или считать 25K заменой 9K по имени.

На каждую конфигурацию обязательны отдельные: RTL-симуляция → Gowin PnR → STA/CDC → SRAM hardware PASS. Наличие одного аппаратного PASS не подтверждает другой target.
