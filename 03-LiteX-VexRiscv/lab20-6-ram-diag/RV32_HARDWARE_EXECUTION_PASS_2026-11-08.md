# LAB-20.6: RV32I RAM-only hardware execution — PASS

**Дата испытания:** 2026-11-08.  
**Операторский источник:** полный вывод `litex>` COM25 на реальной Sipeed Tang Nano 20K, предоставлен в диалоге.  
**Плата / SoC:** Tang Nano 20K, заводской LiteX BIOS (`b05c3069`), VexRiscv_Min @ 48 MHz.  
**Образ:** `snapshot.bin` (740 байт, 185 слов, RV32I+Zicsr), загружен в SDRAM по `0x40010000`.  
**SHA-256 BIN:** `def94e225021f654258cd2760a32c63343a0ade98b4f770882e63a2f17255a0e`.  
**Вход:** `litex> boot 0x40010000`.  
**Статус:** `LAB20_6_RV32_HARDWARE_EXECUTION_PASS / UART_SELF_OBSERVATION_PASS`.

## Полный исходный протокол с платы

```text
litex> boot 0x40010000
Executing booted program at 0x40010000

--============= Liftoff! ===============--

PiKoSoL LAB20.6 RAM-only snapshot BEFORE UART output
TXEMPTY    = 0x00000001
TXFULL     = 0x00000000
RXEMPTY    = 0x00000001
EV_STATUS  = 0x00000001
EV_PENDING = 0x00000001
EV_ENABLE  = 0x00000003
RXFULL     = 0x00000000
MSTATUS    = 0x00000080
MIE        = 0x00000880
IRQ_MASK   = 0x00000000
IRQ_PENDING= 0x00000000
TXEMPTY_AFTER_PRINT = 0x00000000
LAB20.6 HOLD - press physical RESET to return to BIOS
```

## Что доказано непосредственно

1. Заводской LiteX BIOS перешёл к пользовательскому коду по адресу `0x40010000` (наблюдался `Liftoff!`).
2. Исполнился **наш** образ RV32I: текст отчёта, значения CSR и финальная строка `LAB20.6 HOLD` соответствуют исходному `snapshot.S`.
3. Программа записала до печати 11 показаний в блок SDRAM `0x40011000`, после печати заголовка записала двенадцатое значение по `0x40011038`, затем вывела их. Эта последовательность **подтверждена источником кода и фактическим выводом**, но отдельный дамп структуры в SDRAM после старта не снят.
4. До первого символа, отправленного программой в UART, `TXEMPTY=1`. После вывода заголовка: `TXEMPTY_AFTER_PRINT=0`. Это **прямой экспериментальный аргумент в пользу эффекта самонаблюдения**, объясняющий прежние нулевые показания команды `mem_read 0xF0003018`: сама диагностика печатает до считывания регистра TX FIFO.
5. Образ до запуска был полностью прочитан из реальной SDRAM и проверен: [протокол 740/740 байт](SDRAM_HARDWARE_PASS_2026-11-08.md).
6. Кода изменения FPGA конфигурационной Flash в образе нет; использовалась штатная SDRAM и UART.

## Регистры, считанные в реальной программе

| Параметр | 32-разрядное значение | Объяснение |
|---|---|---|
| `TXEMPTY` до собственной печати | `0x00000001` | FIFO TX пуста в момент первого снимка |
| `TXFULL` | `0x00000000` | FIFO TX имеет место для следующего байта |
| `RXEMPTY` | `0x00000001` | FIFO RX пуста в момент чтения |
| `EV_STATUS` | `0x00000001` | Текущий сигнал UART TX-ready активен |
| `EV_PENDING` | `0x00000001` | Бит TX-события ожидает подтверждения (latched) |
| `EV_ENABLE` | `0x00000003` | Разрешены TX и RX события UART |
| `RXFULL` | `0x00000000` | FIFO RX не заполнена |
| `MSTATUS` | `0x00000080` | `MPIE` bit7 = 1, global `MIE` bit3 = 0 |
| `MIE` | `0x00000880` | `MTIE` bit7 и `MEIE` bit11 разрешены, но global MIE выключен |
| `IRQ_MASK` (`0xBC0`) | `0x00000000` | Источники внешнего IRQ VexRiscv замаскированы |
| `IRQ_PENDING` (`0xFC0`) | `0x00000000` | В CPU-специфическом CSR нет ожидающих IRQ |
| `TXEMPTY_AFTER_PRINT` | `0x00000000` | FIFO TX уже не пуста после начала собственного UART-вывода |

**Важное различие:** `EV_PENDING=1` говорит о зафиксированном UART-событии, но не об обработанном процессором прерывании. Во время измерения `MSTATUS.MIE=0` и `IRQ_MASK=0`, поэтому событие не доказывает доставку IRQ в CPU. Происхождение конкретного pending-бита без временной трассы не определено; он согласуется с предшествующим выводом BIOS и событиями TX-ready.

Ранее `mem_read 0xF0003018` возвращал `txempty=0`: исходник BIOS `dump_bytes()` печатает `Memory dump:` и адрес **до** чтения целевого регистра. Наша программа исправляет этот методический дефект: первый снимок сделан после конечной задержки и до собственной печати; второй — после вывода. Утверждение не распространяется автоматически на все возможные причины `txempty=0` в других ситуациях.

## Границы доказанного

- Подтверждено: получение полного текста по COM25; исполнение собственной пользовательской программы из SDRAM; чтение MMIO/CSR; собственный UART вывод; HOLD.
- Не подтверждено отдельно: визуальное состояние UART TX FIFO на уровне сигналов в заданные такты; реальный вход в IRQ/trap обработчик; работа по аппаратному прерыванию; повторный вход в заводской BIOS без RESET; сохранность SDRAM после RESET.
- Все 12 отсчётов последовательные, не атомарные; наблюдение до печати относится к моменту после передачи управления BIOS и программной задержки, а не к аппаратному reset.
- `manifest.json` и `generate_commands.py` содержат **исходные build-time метаданные** (включая `hardware_pass=false` до испытания) и сознательно не изменяются задним числом. **Этот протокол и JSON-квитанция являются источником актуального аппаратного статуса**.

## Завершение и безопасный возврат

Программа находится в `HOLD` (бесконечный цикл). Для возвращения `litex>` нажать аппаратную кнопку **RESET**. Ни Flash, ни конфигурационный bitstream для восстановления изменять не требуется.
