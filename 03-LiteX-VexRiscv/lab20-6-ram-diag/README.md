# PiKoSoL LAB-20.6 — VexRiscv RAM-only Diagnostics v0.1.0

**Tang Nano 20K · factory LiteX BIOS (2023-03-13) · VexRiscv_Min @ 48 MHz**  
**Статус:** `BUILD_PASS / RV32_SIM_PASS / BOARD_TEST_PENDING`.

Это первая самостоятельная программа RV32I+Zicsr для уже работающего **заводского** SoC LiteX. Она измеряет состояние UART **до собственного вывода**, сохраняет снимок в SDRAM, затем печатает результат. Второе чтение `TXEMPTY_AFTER_PRINT` проверяет, как на FIFO влияет печать самой диагностической программы. Не требует Gowin, изменённого FPGA bitstream или записи во Flash.

**Важно:** мы пока **не запускали** именно этот бинарник на физической Tang Nano 20K. Проверены сборка, машинные инструкции и программная модель исполнения; статус BOARD PASS присваивается только после твоей аппаратной проверки.

## Что именно меняется на плате

- Запись **740 байт в оперативную SDRAM** начиная с `0x40010000`.
- Запуск RV32I кода командой BIOS `boot 0x40010000` (отдельный, явный шаг).
- Запись снимка в SDRAM `0x40011000` (60 байт), чтение 7 UART MMIO и 4 CPU CSR; **не читаем** UART `rxtx` до снятия снимка.
- После измерения программа записывает символы в `uart_rxtx` `0xF0003000` и выводит отчёт в терминал.
- После отчёта программа остаётся в бесконечном цикле. **Для возврата к заводскому `litex>` нажми аппаратный RESET платы.**
- **Никакого программирования FPGA, Flash, загрузочного сектора, внешних флеш-микросхем или SD-карты.**

**Запуск — не является обычным вызовом функции:** исходник BIOS LiteX `boot()` имеет `noreturn`, отключает прерывания и передаёт управление приложению. Самостоятельное приложение не возвращается в BIOS. Если не появится вывода, использовать физический RESET; не предпринимать запись во Flash ради восстановления.

## Как выполнить на Windows (COM25, 115200 8N1)

На ПК, где находится рабочий репозиторий:

```powershell
Set-Location C:\GitHub\Sipeed-FPGA
git pull --ff-only
Set-Location .\03-LiteX-VexRiscv\lab20-6-ram-diag
```

**Шаг A. Проверить пакет без подключения к плате.** Команда *ничего не отправляет*:

```powershell
pwsh -NoProfile -File .\upload.ps1
```

**Шаг B. Закрой прежнюю программу UART/терминал**, если она удерживает COM25. Загрузка с проверкой всех 740 байт, без запуска:

```powershell
pwsh -NoProfile -File .\upload.ps1 -PortName COM25 -Upload
```

Успешная загрузка должна закончиться сообщением `PASS: 740 bytes SDRAM load/readback verified...`. Скрипт отправляет 185 `mem_write` **только в SDRAM**, затем сравнивает прочитанные 16-байтные блоки с опубликованным, защищённым SHA-256 образом. При любой ошибке выполнение прекращается до `boot`.

**Шаг C. Запустить вручную.** После закрытия скрипта открой LiteX UART-консоль COM25 и выполни:

```text
litex> boot 0x40010000
```

После отчёта BIOS не вернётся к приглашению `litex>` — это ожидаемо. Нажми физическую кнопку RESET на плате и дождись нового старта заводского BIOS.

**Альтернатива (единый запуск):** если хочешь увидеть отчёт сразу в окне PowerShell вместо переключения терминалов:

```powershell
pwsh -NoProfile -File .\upload.ps1 -PortName COM25 -Upload -Boot
```

Это явным параметром `-Boot` включает **необратимую до RESET передачу управления**. Параметр `-Upload` без `-Boot` ничего не запускает. Порт COM25 должен быть свободен.

## Ожидаемые данные

Пример, полученный **только в программной модели**, а не измеренный на плате:

```text
PiKoSoL LAB20.6 RAM-only snapshot BEFORE UART output
TXEMPTY    = 0x00000001
TXFULL     = 0x00000000
RXEMPTY    = 0x00000001
EV_STATUS  = 0x00000001
EV_PENDING = 0x00000000
EV_ENABLE  = 0x00000003
RXFULL     = 0x00000000
MSTATUS    = 0x00001800
MIE        = 0x00000880
IRQ_MASK   = 0x00000000
IRQ_PENDING= 0x00000000
TXEMPTY_AFTER_PRINT = 0x00000000
LAB20.6 HOLD - press physical RESET to return to BIOS
```

**Числовые значения выше не прогноз в строгом смысле:** в живом устройстве могут отличаться. 

- `TXEMPTY` — снимок перед первым собственным символом после задержки, позволяющей затихнуть предыдущему выводу BIOS. Если значение `1`, FIFO TX пуста в этот момент.
- `TXEMPTY_AFTER_PRINT` — второй снимок сразу после первой напечатанной строки. Если `0`, UART действительно занят данными нашей диагностической программы.
- `MSTATUS`, `MIE`, `IRQ_MASK`, `IRQ_PENDING` относятся к состоянию **после вызова `boot()`**, а не к прежнему состоянию интерактивного BIOS: код BIOS отключает прерывания при передаче управления.
- Снимки **не являются атомарными**, регистры считываются последовательно. Задержка до первого снимка не гарантирует пустоты внешнего буфера по спецификации; это управляемый опыт с измерением.

## Карта снимка SDRAM

| Адрес | Смещение | Содержимое |
|---|---:|---|
| `0x40011000` | `+0x00` | Магия `0x504B534C` (PKSL) |
| `0x40011004` | `+0x04` | Версия и счётчик `0x0001000B` |
| `0x40011008` | `+0x08` | `TXEMPTY` до печати |
| `0x4001100C` | `+0x0C` | `TXFULL` |
| `0x40011010` | `+0x10` | `RXEMPTY` |
| `0x40011014` | `+0x14` | `EV_STATUS` |
| `0x40011018` | `+0x18` | `EV_PENDING` |
| `0x4001101C` | `+0x1C` | `EV_ENABLE` |
| `0x40011020` | `+0x20` | `RXFULL` |
| `0x40011024` | `+0x24` | `MSTATUS` |
| `0x40011028` | `+0x28` | `MIE` |
| `0x4001102C` | `+0x2C` | VexRiscv `IRQ_MASK` CSR `0xBC0` |
| `0x40011030` | `+0x30` | VexRiscv `IRQ_PENDING` CSR `0xFC0` |
| `0x40011034` | `+0x34` | Маркер завершения **первого** снимка `0x454E4F44` (DONE) |
| `0x40011038` | `+0x38` | `TXEMPTY` после печати первой строки |

Этот блок заполняется **до или во время** работы программы; если после `boot` нажать RESET, SDRAM может быть переинициализирована, поэтому не следует считать содержимое снимка сохраняемым после перезагрузки. Надёжный способ фиксации результата — скопировать выведенный UART-отчёт.

## Сборка при необходимости

Linux / Windows WSL (Clang 17+, LLVM tools и Python 3):

```bash
./build.sh
```

Сборка: `-march=rv32i_zicsr`, `-mabi=ilp32`, `-mno-relax`. Скомпонованный адрес — `0x40010000`; bin предназначен для записи по адресу целиком, **не** для загрузки ELF в BIOS. Для Windows готовый BIN уже включён в репозиторий, компилятор там не нужен.

## Источники и пределы уверенности

- [Исторический LiteX boot.c](https://github.com/enjoy-digital/litex/blob/b05c3069/litex/soc/software/bios/boot.c) — `boot` является `noreturn`, выполняет `uart_sync`, отключение прерываний и flush кэшей.
- [cmd_boot.c](https://github.com/enjoy-digital/litex/blob/b05c3069/litex/soc/software/bios/cmds/cmd_boot.c) — синтаксис `boot <address>`.
- [cmd_mem.c](https://github.com/enjoy-digital/litex/blob/b05c3069/litex/soc/software/bios/cmds/cmd_mem.c) — синтаксис `mem_write <address> <value>` и `mem_read`.
- [uart.py](https://github.com/enjoy-digital/litex/blob/b05c3069/litex/soc/cores/uart.py) — UART MMIO-регистры, FIFO и события.
- [LAB-20.5 — аппаратная проверка семи UART CSR](../../docs/lab20/rom-explorer/UART_CSR_HARDWARE_2026-11-07.md).

Нет утверждения, что **аппаратный** запуск успешен: это проверит оператор Tang Nano 20K. При публикации новой версии сохраним SHA-256 и результаты лаборатории.
